- Версия Night Shift после исправления: **1.1.1**. Протокол функциональных проверок: plugin-owned-v1.
- Simply Localize: package.json **2.0.2**, HEAD **d2f77957ee30e06309a8a16ffa7c876929ad6384**. Исходники пакета не изменялись. Runtime SHA-256: `568b7b2fdbaa081676cccbab3f6a4477673d65205e78d9f1788bf0badf642885`.
- Git describe содержит dirty из-за изменений проекта/документации; это не изменение исходников локализатора. Commit/push не выполнялись.

## 2. Откуда взялись ссылки и почему их можно убрать

### PC_Renderer.asset: семь устаревших ресурсов

Все семь GUID находились в блоке `probeVolumeResources`: probeVolumeDebugShader, probeVolumeFragmentationDebugShader, probeVolumeOffsetDebugShader, probeVolumeSamplingDebugShader, probeSamplingDebugMesh, probeSamplingDebugTexture, probeVolumeBlendStatesCS.

Проверен исходник установленного URP: `Packages/com.unity.render-pipelines.universal/Runtime/Deprecated.cs`, класс ProbeVolumeResources и одноимённое поле помечены Obsolete. Отладочные ресурсы перенесены в ProbeVolumeDebugResources, ресурс смешивания — в ProbeVolumeRuntimeResources. Поиск обращений в установленном URP/Core не выявил использования старого поля рендерера; актуальный ProbeReferenceVolume.Debug.cs использует новый контейнер ресурсов.

Перед очисткой каждый из семи SerializedProperty проверен: objectReferenceValue был null. Существующие рабочие ресурсы не заменялись. Ссылки очищены через SerializedObject/ApplyModifiedPropertiesWithoutUndo; новые GUID не создавались.

### DefaultVolumeProfile.asset: девять неработающих subasset-записей

Четыре ранее найденных неразрешённых GUID:

| Имя записи | Отсутствующий GUID |
|---|---|
| OutlineVolumeComponent | 60f3b30c03e6ba64d9a27dc9dba8f28d |
| TestAnimationCurveVolumeComponent | 0fd9ee276a1023e439cf7a9c393195fa |
| OasisFogVolumeComponent | 5a00a63fdd6bd2a45ab1f2d869305ffd |
| TestVolume | 74955a4b0b4243bc87231e8b59ed9140 |

Кроме них, штатный AssetDatabase.GetScriptableObjectsWithMissingScriptCount выявил пять записей с m_Script: {fileID: 0}: CopyPasteTestComponent1/2/3, VolumeComponentSupportedEverywhere и VolumeComponentSupportedOnAnySRP. В прежний поиск GUID они не попадали, поскольку GUID уже отсутствовал. Имена, fileID и содержимое всех девяти записей доступны в [исходном профиле](artifacts/DefaultVolumeProfile.asset.before.txt); отдельный повторяющий их JSON удалён.

Ни одна из девяти записей не загружалась как действующий VolumeComponent: LoadAllAssetsAtPath возвращал для них null. Активный профиль содержал **19 рабочих компонентов**. Исходники отсутствующих четырёх классов в проекте и установленных пакетах не найдены; подключать неизвестную зависимость ради неработающих тестовых записей не требуется. Названия двух из четырёх похожи на пользовательские эффекты, но их визуальное поведение невозможно восстановить по одному имени — отчёт не утверждает, что они никогда не были нужны в другом проекте. Для текущего полигона они уже не участвовали в изображении.

Девять записей удалены штатным `AssetDatabase.RemoveScriptableObjectsWithMissingScript`, затем выполнены SaveAssets и ForceReserializeAssets для двух исправляемых файлов. Возвращённое число удалений — 9, повторный счётчик — 0. Полные исходные файлы сохранены как *.before.txt, алгоритм с проверками предпосылок — [repair.cs](artifacts/repair.cs).

## 3. Что сохранилось и что изменила сериализация

Сравнение EditorJsonUtility до и после:

- Все 19 рабочих компонентов профиля, их типы и сериализованные значения идентичны.
- Renderer Features, включая SSAO и его настройки, идентичны.
- Данные рендерера вне очищенного probeVolumeResources идентичны.
- Исходные **414 .meta** репозитория/проекта не изменены; GUID двух исправленных ассетов сохранены.
- Сцены, материалы, свет, локализованные текстуры и runtime-код не редактировались.

Unity при повторной сериализации также удалила восемь старых ссылок из SSAO subasset: семь элементов m_BlueNoise256Textures и m_Shader. В актуальном ScreenSpaceAmbientOcclusion эти поля private без SerializeField; ресурсы поступают из GraphicsSettings через ScreenSpaceAmbientOcclusionPersistentResources / DynamicResources. Это очистка данных прежней схемы сериализации, а не отключение SSAO. Новые нулевые поля xrSystemData и форматов depth добавлены штатным сериализатором с уже существовавшими эффективными значениями по умолчанию.

Поэтому число текстовых GUID-ссылок уменьшилось с 928 до 909: удалены 11 неразрешённых ссылок и 8 устаревших сериализованных SSAO-ссылок. Для изучения diff сравните [исходный рендерер](artifacts/PC_Renderer.asset.before.txt) и [исходный профиль](artifacts/DefaultVolumeProfile.asset.before.txt) с текущими Assets/Settings/PC_Renderer.asset и DefaultVolumeProfile.asset. Результат сравнения параметров — [settings-comparison.json](artifacts/settings-comparison.json). rendererEffectiveSerializationIdentical=false включает намеренно очищенный блок; rendererExceptObsoleteBlockIdentical=true подтверждает остальные данные. Отдельные копии исправленных файлов, diff и дампы тех же настроек удалены.

## 6. Воспроизведение и восстановление

Для аудита используйте штатные AssetDatabase.GetScriptableObjectsWithMissingScriptCount, LoadAllAssetsAtPath и EditorJsonUtility.ToJson: сравните все рабочие Volume-компоненты и rendererFeatures до/после, исключая только устаревший блок probeVolumeResources при сравнении самого рендерера. Временные скрипты-обёртки удалены. Сохранённый repair.cs запускается через unity command script eval --file <путь к repair.cs> --project-path <проект>. Он требует исходного состояния с девятью сломанными записями; после исправления должен остановиться на проверке предпосылок, а не удалять другой контент.

Для повторного аудита текущего состояния используйте RepositoryMigrationChecks.Verify и GetScriptableObjectsWithMissingScriptCount для профиля. Возвращать исходное состояние при необходимости следует из сохранённых *.before.txt в те же два .asset, сохраняя нынешние .meta; после восстановления нужен повторный импорт. Нельзя восстанавливать все файлы проекта из старого архива поверх более новых изменений.

Контрольные изображения доказывают отсутствие изменения текущего вида при удалении неработающих данных. Они не восстанавливают исторический вид неизвестных эффектов Outline/Oasis и не подтверждают поведение гигабайт локализованных ресурсов.

Редакция 1.1: удалены скриншоты, логи, временные команды и дубли данных. Исходные два файла MIG-001 и алгоритм исправления сохранены, поскольку их сломанное состояние отсутствует в родительском Git-коммите. Результаты прежних проверок не пересчитывались.
