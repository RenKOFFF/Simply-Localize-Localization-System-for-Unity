# Этапы стабилизации: фактическая нумерация

После исходного аудита форматирование и профили были разделены на два этапа, поэтому нумерация разошлась с первым планом. Этот файл фиксирует текущий порядок, выбранный после уточнения задачи 2026-11-15.

| Этап | Объём |
|---|---|
| 0–1, выполнен | Регрессии загрузки, Reload, fallback, замена провайдера |
| 2, выполнен | Форматирование, plural-правила, шаблоны |
| 3, выполнен | Языковые профили, шрифты, overrides |
| 4, выполнен | Bootstrap, статическое состояние, конфигурация, диагностика и Coverage |
| 5, выполнен | Безопасное чтение и сохранение `_meta.json` |
| 6, выполнен | CSV-импорт и безопасное сохранение переводов, метаданных и новых профилей |
| 6.1, выполнен | Поиск конфига, независимое логирование, контексты только с ассетами |
| 6.2, выполнен | Фиксированный автозапуск, настройка через окно и Editor API, отделение внутренних тестов |

В этапе 5 сохранены публичные сигнатуры и формат метаданных. Неверные типы и повреждённые данные теперь дают диагностику вместо зависания/частичного чтения. После ошибки чтения необходимо исправить файл и перезагрузить данные; SaveMeta отказывается перезаписывать такой файл. При внешних изменениях также требуется перезагрузка. Запись выполняется через временный файл в том же каталоге и атомарную замену. Неизвестные поля сохраняются, пустые известные поля продолжают поддерживаться.

Проверка на Windows / Unity 6000.0.62f1: 31 новый тест метаданных; полный EditMode — 218 passed, PlayMode — 26 passed, без ошибок и пропусков. Два теста блокировок файлов используют семантику FileShare Windows и на других ОС пропускаются. Воспроизведение до исправления: Unicode/управляющие escape-последовательности повреждались. Сценарии с потенциальным зависанием старого парсера запускались после замены парсера.

В этапе 6 добавлены полная проверка CSV, неизменяемый план импорта и окно предпросмотра. Пустые ячейки по умолчанию пропускаются; явная очистка доступна через переключатель и `CsvEmptyCellPolicy.Clear`. Старые сигнатуры и форматы сохранены. До применения новые профили не создаются.

Сохранение переводов и метаданных использует подготовку всех записей, замену файлов и откат при исключении. Применение CSV также защищает конфиг и новые профили. Сохраняются история ключей, дополнительные поля JSON и правки в памяти при ошибке. Повреждённые CSV, опасные пути, устаревший предпросмотр и внешние изменения переводов/метаданных блокируют запись. Это не журнал восстановления после падения процесса: при отказе самого отката сохраняются резервные файлы с указанием путей.

Проверка 2026-11-16 на Windows / Unity 6000.0.62f1, после переустановки редактора на диск D: 52 теста CSV/сохранения; полный EditMode — 270 passed, PlayMode — 26 passed, без ошибок и пропусков. Проверены блокировки, read-only, внешние изменения, ошибочные CSV, устаревший предпросмотр, откат после создания профиля и фактической сериализации конфига, сохранение несохранённых правок конфига и повторное применение после ошибки. Тесты FileShare с атрибутом Platform("Win") на других ОС пропускаются.

Тест заблокированного config.asset воспроизвёл зависание внутри нативного сохранения Unity. Теперь доступ проверяется до вызова Unity; финальная регрессия проходит без зависания. Ошибка после успешной сериализации конфига моделируется управляемым исключением: это позволяет проверить полный откат без зависания редактора.

В редакторе проверены окно предпросмотра, выбор строки и кнопка Cancel: значения в памяти и хеши всех файлов полигона остались прежними. Интеграционная проверка сохранённой сцены прошла через её реальные UI-кнопки: en/ru/pl, TMP и legacy Text, plural, параметры, fallback, профили/override, Reload, провайдер и повторное включение компонентов.

### 6.1 — выполнен: точечные проблемы runtime

- **SL-001, сначала:** убрать корневое `Resources.LoadAll<LocalizationConfig>("")` из автоматического поиска конфигурации. Выбрать адрес или небольшой каталог регистрации с совместимым переходом для существующих конфигураций. Не требовать ручного переноса пользовательских переводов. Регрессии: одна/нет/несколько конфигураций, ручная и автоматическая инициализация; отдельный чистый Player подтверждает отсутствие загрузки посторонних языковых ресурсов до запроса игры.
- **SL-009:** исключить неожиданное влияние конструктора второго менеджера на Info-логирование первого. Сохранить публичный API логирования и явно определить смысл глобальных переключателей. Регрессия двух менеджеров с противоположными настройками; отдельно проверить предупреждения/ошибки и настройки для сборки.
- **SL-011:** явно поддержать контекст только с ассетами, не заставляя его искать отсутствующие JSON. Совместимое значение новых настроек по умолчанию должно сохранить поведение существующих конфигураций. Регрессии text-only, asset-only и mixed, fallback, Reload и замена провайдера; предупреждения о действительно отсутствующих текстах не скрывать.

Каждый пункт — отдельное исправление с регрессией и коммитом. Завершение: полный EditMode/PlayMode и новый запуск Night Shift; уменьшение предупреждений само по себе не доказывает исправление загрузки или освобождения ресурсов. Этап выполнен: d057a9f/897226f (SL-001), 762faf8 (SL-009), 47cd8fe (SL-011). Полный EditMode — 294 passed, PlayMode — 26 passed; новый Night Shift — 194 успешных утверждения, 0 AudioClip на старте, 3 предупреждения вместо 34. ## Принятые решения по загрузчикам

Resources остаётся встроенным вариантом. Addressables — будущая необязательная интеграция. Файловые языковые пакеты интересны для пользовательских переводов готовой игры (например, добавление игроком польского языка в настольной версии с itch.io): понадобятся обнаружение языка без Unity, метаданные пакета, проверка формата, fallback и поддерживающие символы шрифты. Это будущая возможность, в этап 6.1 она не входила; просто чтение JSON её полностью не решает.
