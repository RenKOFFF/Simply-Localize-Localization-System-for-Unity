# Этап 7: переименование ключей и ссылок

Unity 6000.0.62f1, локальный UPM-пакет, ветка dev/localization-stability. База до изменений: dd9787d.

## Что изменилось

В Simply Localize → Translations и Assets команда Rename теперь проверяет операцию целиком до записи. Например, переименование menu.play → ui.play переносит переводы всех загруженных языков, описание и историю ключа, затем обновляет соответствующие сериализованные ссылки. Если сохранение не завершилось, сохранённые к этому моменту файлы восстанавливаются из временных копий, а открытые объекты — из снимков состояния.

Раньше переводы сохранялись раньше ссылок. Ошибка на сцене или префабе оставляла проект с частично выполненным переименованием. Открытые сцены только помечались изменёнными, ScriptableObject и пользовательские поля не обрабатывались, а последовательный пакетный проход мог превратить A → B → C вместо двух независимых замен.

Теперь поддерживаются:

- Открытые сохранённые и закрытые сцены, включая ключи с Unicode и экранированными символами. Закрытые сцены читаются через Unity, без поиска сырого текста YAML.
- Префабы, вложенные префабы и варианты. Наследуемые значения обновляются через источник; лишние overrides не создаются.
- ScriptableObject и его sub-assets, пользовательские поля с [LocalizationKey] или [LocalizationPreview], вложенные списки и массивы. Циклы в графе [SerializeReference] обходятся без повторного входа.
- Независимые текстовые и ассетные ключи. Переименование текста не меняет ключ аудиоклипа или картинки с таким же именем.
- Одновременные пакетные замены, в том числе A → B, B → A. Исходные значения фиксируются до применения.
- Проверки конфликтов ключей и метаданных, внешнего изменения JSON, read-only, файловой блокировки, несохранённых изменений и Prefab Mode. Сообщение об ошибке остаётся в окне переименования.

Сохраняются GUID и существующие форматы данных, дополнительные поля JSON и метаданных, значения переводов, привязки ресурсов в таблицах. Глобальный AssetDatabase.SaveAssets больше не используется этой операцией.

## Совместимость и расширение

Существующие публичные сигнатуры KeyReferenceUpdater.UpdateReferences, EditorLocalizationData.RenameKey и методы таблиц сохранены. Низкоуровневые RenameKey по-прежнему меняют данные в памяти; для полной операции добавлен LocalizationKeyRenamer.RenameText / RenameAssets. Окно использует этот же Editor API.

Вызовы из пользовательского Editor-скрипта возможны без форка пакета:

    using SimplyLocalize.Editor.Data;
    using SimplyLocalize.Editor.Utilities;

    var data = new EditorLocalizationData();
    data.Load(config);
    LocalizationKeyRenamer.RenameText(data, "menu.play", "ui.play");
    data.FlushPendingAssetRefresh();

Опциональный searchRoots ограничивает область поиска ссылок Unity-путями, например new[] { "Assets/MyGame" }. При его использовании вызывающий код отвечает за ссылки за пределами выбранной области. Пользовательские атрибуты LocalizationKey / LocalizationPreview обозначают текстовые ключи, как и их существующие инспекторы.

Внутренние регрессии и вспомогательные тестовые типы находятся только в playgrounds/SimplyLocalize-Lab, за пределами src/SimplyLocalize. Они не добавлены в распространяемый пакет.

## Границы поведения

- Строковые литералы в C#, произвольные непомеченные строки, UnityEvent-аргументы и внешние документы автоматически не переписываются. Такие обращения разработчик переносит сам.
- Автоматическое переименование не редактирует пакетные ассеты. Совпавшая ссылка внутри Packages останавливает операцию до записи, включая локальную UPM-зависимость. Нужно обновить источник пакета либо отключить автоматическое обновление ссылок и перенести обращения вручную.
- Затронутые сохранённые сцены и ассеты с несохранёнными правками нужно сначала сохранить. Для затронутого префаба необходимо выйти из Prefab Mode. Открытые безымянные сцены нужно сохранить перед обработкой закрытых сцен — это ограничение additive-загрузки Unity.
- Ctrl+Z не отменяет всю операцию, которая сохраняет несколько файлов. Об этом написано непосредственно в окне. Отдельный API обновления ссылок поддерживает Undo, когда изменения целиком находятся в безымянных открытых сценах и не затрагивают файлы.
- После отката содержимое открытой сцены восстановлено, но Unity может оставить её dirty: публичного метода очистки этого флага без сохранения нет. Исходный файл сцены уже восстановлен; это не частично сохранённое переименование.
- Откат рассчитан на перехваченные ошибки, а не на отключение питания или аварийное завершение процесса. Если восстановление файла само не удалось, существующий механизм транзакций сохраняет резервную копию и сообщает её путь.
- Поиск выполняется синхронно по ассетам проекта. Индексация, фоновые операции и измерения на больших проектах не входили в этот этап.

## Проверки

Добавлены 22 регрессионных случая. В том числе ошибки после фактической записи переводов, сцен, префабов и таблиц ассетов; сравнение всех файлов фикстуры с исходными байтами; сохранность ссылок на ресурсы; циклические и вложенные данные; независимость типов ключей; состояние открытых/выгруженных сцен; незаписанная ссылка в Prefab Mode; локальный UPM-путь; файловая блокировка без зависания нативного сохранения Unity.

Полный прогон: **361/361 EditMode**, **26/26 PlayMode**, без ошибок, пропусков и inconclusive. Результаты Unity Test Runner: [EditMode](editmode.json), [PlayMode](playmode.json).
