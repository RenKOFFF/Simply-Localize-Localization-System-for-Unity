# Что изменится для игры при обновлении с OpenUPM 2.0.2

На 24 ноября 2026 года OpenUPM отдаёт `com.renkoff.simply-localize@2.0.2` как `latest`. Сравнивались распакованный архив реестра (SHA-1 `050ea21210fdd1c65c8e09705f61227fa3d6a9e0`, ревизия `c1f0d7a`) и ветка `dev/localization-stability` на `d252c0a`. В манифесте ветки также стоит `2.0.2`. Первоначальное предложение было 3.0.0. Для выпуска выбран **2.1.0** с явным предупреждением о несовместимых изменениях. Даже игра со стандартным загрузчиком должна заново настроить проект, а игровые скрипты со старым API смены языка потребуют правок. [Запись реестра](https://package.openupm.com/com.renkoff.simply-localize) · [Страница OpenUPM](https://openupm.com/packages/com.renkoff.simply-localize/)

| Что использует игра | Как работало в 2.0.2 | Что сделать при обновлении |
|---|---|---|
| Автозапуск | Поиск всех `LocalizationConfig` в Resources и выбор первого | Создать единый конфиг в окне Simply Localize. Setup сохраняет его в `Assets/SimplyLocalize/Resources/SimplyLocalizeSettings.asset`. Восстановить список языков, язык по умолчанию и fallback. |
| Переводы, картинки и звук | Старый конфиг и провайдер определяли, где искать содержимое языка | Подключить существующие JSON и таблицы по языкам через **Settings → Content sets → Connect a source**. Для небольшой игры достаточно Main/Common. Зарегистрировать найденные текстовые ключи, сверить записи таблиц и ссылки на объекты. У скрипта `LocalizationAssetTable` сохранились GUID и сериализованный список записей. |
| Текст и озвучка с разными настройками языка | Игра с несколькими конфигами сама координировала переключение | Оставить текст и субтитры в Main с `en` и `ru`. Создать Voice с `en`, если голос должен оставаться английским. Переключение Main меняет субтитры, а клип остаётся прежним. |
| Компоненты в сценах и префабах | У `LocalizedText` и `LocalizedAsset` был строковый ключ | GUID скриптов и поле `_key` сохранились. Старую привязку можно оставить, если ключ однозначно доступен в загруженных данных основного канала. При переносе записи в другой канал явно выбрать её на компоненте. Для набора с загрузкой по требованию обеспечить загрузку к моменту показа. |
| Ручной запуск из сцены | `LocalizationBootstrap` ссылался на старые конфиг и профиль языка | На существующем компоненте назначить новый конфиг и заново задать код языка, если использовалось переопределение. GUID скрипта сохранился, типы обоих полей изменились. |
| Шрифты и типографика | Общие параметры хранились в `LanguageProfile`, локальное переопределение ссылалось на профиль | Перенести общие настройки в **Appearance**. На компонентах `LocalizedProfileOverride` заново выбрать язык для каждой старой записи. Теперь запись выбирается по строке `languageCode`. При пустом коде компонент пропустит запись без ошибки компиляции. |
| Свой загрузчик | Игра подставляла провайдер через `SetDataProvider` | Реализовать `ILocalizationSourceProvider` в проекте игры и зарегистрировать его в `LocalizationSourceRegistry`. Успешная загрузка возвращает `LocalizationSourceLease`, через который runtime освобождает данные. Встроенный Resources работает без дополнительного кода. |

## Игровые скрипты

| 2.0.2 | Ветка dev |
|---|---|
| `Localization.Initialize(config)` | `await Localization.InitializeAsync(projectConfig)` |
| `Localization.SetLanguage("ru")` | `await Localization.SetLanguageAsync("ru")` для основного канала |
| `Localization.Reload()` | `await Localization.ReloadAsync()` |
| `Localization.CurrentProfile` | Текущий язык доступен через `Localization.CurrentLanguage`, оформление через `Localization.CurrentAppearance` |
| Перебор профилей через `Localization.AvailableLanguages` | Свойство возвращает список строковых кодов. Обработчики, читавшие поля профиля, нужно обновить. |
| `Localization.Get(key)`, `Localization.GetAsset<T>(key)` | Эти вызовы можно оставить для данных основного канала. Проверить результат после завершения загрузки. |

## Перед выпуском

1. Сохранить копию игры и выписать настройки старых профилей **до** замены пакета. Порядок переноса, включая конфликт со старым ассетом по адресу автозапуска, описан в [инструкции перехода](../../channel-architecture/UPGRADE.md).
2. Обновить примеры в английском и русском README к моменту выпуска. Оба сейчас указывают `2.0.1` для установки и показывают старые вызовы `Initialize` и `SetLanguage`. В changelog назвать ручные шаги для конфига, источников, Bootstrap и переопределений шрифта.
3. Для проверки именно обновления взять копию игры с опубликованной 2.0.2. Сохранить сцену с текстовым ключом, таблицей ассетов, Bootstrap и локальным переопределением шрифта. После замены пакета пройти инструкцию и сравнить старт, текст, озвучку, шрифт и fallback в сборке.

В этом сравнении проверены исходники, манифесты и сериализованные поля. Прежняя [проверка на Unity 2021.3.45f2](../20261124-unity-2021.3.45f2/REPORT.md) покрывает чистую установку dev-версии и работу Windows Player. Результат последующей проверки шага 3 приведён ниже.

## Проверка обновления на 2.1.0

Для выпуска согласован номер **2.1.0**. На Unity 6000.0.62f1 подготовлены и запущены две отдельные Windows x64 Mono сборки. Первая использовала распакованный архив OpenUPM 2.0.2, вторая — локальный пакет 2.1.0 и копию сцены, сохранённой на первой версии. В сцене были явный Bootstrap со ссылками на конфиг и английский профиль, обычный UI Text, русское переопределение шрифта, AudioSource и два строковых ключа компонентов. Автозапуск был выключен, чтобы проверить именно Bootstrap.

В копии изменён вызов смены языка, создан Main/Common и подключены оригинальные en/ru JSON и английская таблица клипов. Зарегистрированы ключи, в Bootstrap назначены новый конфиг и стартовый код. У старой записи шрифта сохранилась ссылка на сам шрифт, поле кода языка было пустым. В него записали `ru`. Оба строковых ключа компонентов сохранились. Сравнение SHA-256 подтвердило побайтовое совпадение исходных JSON, таблицы ассетов и их метафайлов после обновления.

| Проверка в запущенной игре | OpenUPM 2.0.2 | Локальная 2.1.0 |
|---|---|---|
| Язык и надпись | en → ru → en, Hello → Привет → Hello | Те же значения |
| Ключ, пропущенный в ru | English only | English only |
| Английская озвучка | Одна ссылка на клип на всех шагах | Одна ссылка на клип на всех шагах |
| Переопределение шрифта для ru на объекте с legacy Text и LocalizedText | Остался исходный шрифт, хотя в сцене был назначен другой | Применился назначенный русский шрифт, при возврате к en восстановился исходный |

Сцену настроили и перенесли через Editor API в batch mode. Проверки считывали текст и ссылки на клип и шрифт из компонентов Player. Визуальная отрисовка и воспроизведение звука в этот прогон не входили.

### Сохранённые обработчики LocalizedEvent

На Unity 6000.0.62f1 в проекте с OpenUPM 2.0.2 сохранена отдельная сцена с двумя одинаково настроенными компонентами. У каждого была запись для русского профиля с обработчиком `ShowRussian` и резервное событие `ShowFallback` для языков без своей записи. В копию проекта с пакетом 2.1.0 перенесли тот же файл сцены и метафайлы скриптов. После импорта у обеих записей код языка был пустым. У обоих событий сохранились ссылки на объекты-получатели и имена методов.

| Компонент в Windows x64 Mono Player | Старт на en | Переход на ru | Возврат на en |
|---|---|---|---|
| 2.0.2, исходные настройки обоих объектов | Резервное событие | По одному вызову русского обработчика на объект | Резервное событие |
| 2.1.0, в старой записи указан код `ru` | Резервное событие | Один вызов прежнего русского обработчика | Резервное событие |
| 2.1.0, контрольная запись с пустым кодом | Резервное событие | Резервное событие | Резервное событие |

Обе сборки подтвердили результат счётчиками вызовов в игре. Для переноса достаточно заполнить **Language Code** в существующей записи. Повторно привязывать методы не требуется.
