# C5 — окно и редакторские данные (в работе)

Первый шаг подготавливает чтение текстов для нового окна. Само окно пока
остаётся на прежней модели; этот шаг не объявляется завершением C5.

## Снимок выбранного набора

EditorProjectTextData.Load принимает проектный конфиг, ID канала и набора.
Без явного выбора используются Main и его default-набор. Снимок содержит
зарегистрированные текстовые записи со стабильными ID и тексты только из
точных источников выбранного набора, для языков выбранного канала.
Таблицы ассетов и оформление не загружаются ради текстового предпросмотра.

- TryGetDirect показывает исходную запись, включая пустое значение.
- TryResolve учитывает per-language и общий fallback канала и сообщает язык
  и источник найденного непустого текста.
- GetUnregistered показывает записи файлов, ещё не зарегистрированные в наборе.
  Они не становятся runtime-ключами автоматически. Даже совпадающие лишние
  ключи из разных файлов сохраняют отдельное происхождение.
- Снимок не меняется при последующей правке конфига или источника. Для обновления
  вызывается Load; ошибка не возвращает частично прочитанное состояние.
- Одинаковый локальный ключ в разных наборах не смешивается. Дубликат
  зарегистрированного ключа в источниках одного языка/набора даёт ошибку
  с обоими адресами, как конфликт, требующий явного решения.

ResourcesEditorTextReader индексирует адреса AssetDatabase, затем читает точный
TextAsset с диска, без Resources.Load и без запуска игрового runtime. Правка
JSON вне Unity видна при новом Load ещё до реимпорта. Индекс путей относится
к экземпляру reader: после создания/переноса файлов нужно создать новый reader
после AssetDatabase.Refresh. Load без явно переданного reader делает это сам.
Неоднозначный Resources-адрес отклоняется, а не выбирается случайно. Содержимое
папок Editor исключается; размер/память соседних ассетов здесь не измеряются.

Игра может реализовать ILocalizationEditorTextReader в своей Editor-сборке и
передать его в Load, без форка. Источник возвращает скопированный словарь и
необязательный путь ассета. Неизвестный провайдер без reader выдаёт явную ошибку;
он не выглядит пустым набором и не предлагает затереть содержимое. Смешанный
reader может делегировать ResourcesEditorTextReader встроенные адреса.
Интерфейс предназначен для чтения, он не обещает запись произвольного backend.

## Подготовка и сохранение правок

Следующий шаг добавляет LocalizationProjectEdit. Он работает с сохранённым
проектным конфигом и явно включёнными наборами. Сначала сохраняются отдельные
несохранённые правки конфига (например, сделанные в Inspector); затем создаётся
черновик и читаются текущие байты точных текстовых источников этих наборов.
Изменение черновика не меняет живой конфиг, файлы или игровой runtime.

```csharp
using var edit = new LocalizationProjectEdit(config, setId);
edit.SetTranslation(entryId, "ru", "Начать игру");
// Или RenameTextEntry, MoveTextEntry, RemoveTextEntry, RemoveTranslation.
var change = edit.Commit();
LocalizationProjectUndo.Record(change, "Edit localization text");
```

При переносе в другой набор оба набора включаются в конструктор. Идентичность
записи сохраняется; перемещаются исходные значения по всем настроенным языкам.
Для отсутствующей записи с несколькими возможными файлами требуется явно
выбрать источник. Наличие незарегистрированного ключа в месте назначения —
конфликт, а не разрешение затереть его. Разные языки нельзя автоматически
свести в один общий файл с потерей одного перевода.

Если общий JSON ещё используется другой зарегистрированной записью/набором
в этом конфиге, переименование
создаёт новый ключ и оставляет старый для оставшегося потребителя. Удаление
или перенос также проверяет пользователей. Обычная правка значения общего
ключа действует на всех его пользователей: это один общий источник данных.
Изменять адреса источников и одновременно сохранять подготовленные текстовые
правки нельзя: маршрутизация сохраняется отдельно, затем открывается свежий
текстовый черновик. Так правка не попадёт незаметно в уже отключённый источник.

Commit проверяет неизменность конфигурации в памяти и на диске, исходные байты
файлов, однозначность адресов Resources и доступность записи. JSON и конфиг
сохраняются с откатом при ошибке; ошибка оставляет черновик доступным для
просмотра. Запись ограничена редактируемыми ассетами под Assets и не проходит
через junction/symlink. Внешние/пакетные backend не записываются скрытым обходом:
их интеграция может использовать собственный writer и публичную модель конфига.

Неизменённые JSON сохраняют исходные байты. В изменённых сохраняются кодировка,
BOM, перенос строки, неизвестные поля и нетронутые значения. Переформатирование
изменённого JSON допустимо. GUID ассетов и файлов не меняются. Текстовый API не
является редактором AssetTable; это следующая часть C5.

LocalizationProjectChange позволяет явно вызвать Undo/Redo. После регистрации
через LocalizationProjectUndo используется обычная история Unity. Она хранит
отдельную запись транзакции и переключатель направления, поэтому отмена не
восстанавливает устаревшее внутреннее состояние самой транзакции. Конфликт с
внешней правкой останавливает отмену с сообщением; чужой файл не перезаписывается.
Dispose возвращённой записи истории удаляет только эту операцию из Undo.
История живёт в скрытых Editor-объектах, не создаёт ассетов в проекте/UPM;
при выходе из редактора освобождается. Пока не заявляется оптимизация больших
историй: изменённые файлы нужны для точного отката. Неизменённые файлы после
Commit исключаются из истории: Undo не удерживает их байты и не вмешивается
в последующие независимые правки этих файлов. Повторная регистрация одной
транзакции в нативной истории отклоняется. После Record используется Unity Undo,
а не смешанное ручное управление тем же change.Undo/Redo.

Проверен отдельный реальный assembly reload: прежняя динамическая сборка
отсутствовала после перезагрузки, а обычные Undo и Redo восстановили JSON,
конфиг и стабильный ID. AppDomain.Id в этом Unity возвращался как 1 до и после,
поэтому он не использовался как доказательство reload. Временная фикстура удалена;
локальный результат — TestResults/Channels-C5/undo-reload-result.json.

Окно ещё не подключено к этим операциям. Остаются Setup и управление каналами/
наборами, редактор ассетов/оформления, Coverage, CSV, диагностика и визуальная
приёмка. Старая редакторская модель пока нужна существующему окну.

Новые регрессии записи проверяют изоляцию черновика, сохранение расширенных
JSON-полей и кодировки, отсутствие записи при no-op, ID при rename/move,
общий источник нескольких наборов, конфликт целевого ключа, выбор источника,
конфликт двух языков в общем месте назначения, внешнюю правку памяти/диска,
read-only файл, неоднозначность нового Resources-адреса, смену маршрутизации,
явные и нативные Undo/Redo, порядок нескольких операций, внешние изменения
после Undo и повторную регистрацию одной операции. Старые проверки отката CSV
продолжают использовать прежний внутренний TrackExternal; новый приём снимка
байтов имеет отдельное имя TrackExternalSnapshot, без неоднозначной перегрузки.

Итог после исправления конфликта внутреннего helper: **558 EditMode passed**,
0 failed/skipped/inconclusive, Unity 6000.0.62f1 / Windows; 19 новых регрессий
записи и Undo. Компиляция без ошибок. Отчёт:
TestResults/Channels-C5/EditMode-project-edit-full.json. Runtime и Player-код
не менялись; последний полный PlayMode-прогон остаётся 73 passed из C4.

## Создание проекта и языки

Добавлен публичный LocalizationProjectAuthoring: Create/Configure создают один
проектный конфиг Main/Common и точные пустые JSON для выбранных языков.
Настройка не создаёт LanguageProfile и не хранит тяжёлые ссылки в конфиге.
Повторный Configure дополняет существующий конфиг, сохраняет ID, названия и
переводы; ошибка одного языка откатывает всю операцию. Занятый стартовый адрес
не перезаписывается. AddLanguage расширяет Main, не меняя независимые каналы.
Для внешнего backend добавляется определение языка без скрытой записи Resources.

Подготовлены ProjectSetupView и ProjectLanguagesView с общим каталогом языков,
стандартными кодами и прежней палитрой окна. Default/fallback и доступность
относятся к выбранному каналу. Статус plural различает встроенное, custom и
общее правило; последнее предупреждает, но не блокирует язык. Изменения имеют
нативный Undo/Redo и не переключают запущенный runtime. Основное окно пока не
переключено: это проверенные части нового UI, не завершение C5.

Удаление языка снимает определения и привязки, сохраняя исходные файлы.
Повторное добавление подключает сохранённый валидный JSON без изменения байтов
или GUID. Новое создание проекта, в отличие от повторного подключения языка,
не присваивает уже занятые файлы. CreateTextSource/RegisterTextSource позволяют
Editor-скриптам явно создавать или подключать точные источники через транзакцию.
При Undo нового файла удаляются JSON и meta, при Redo восстанавливается GUID.

Исправлено чтение источников под Packages: логический путь AssetDatabase
разрешается через PackageInfo.resolvedPath. Проверка с временным источником в
реальном локальном UPM-пакете подтверждает чтение и отказ от записи в пакет;
редактирование метаданных проекта при этом разрешено. Фикстура удаляется после
проверки и не включается в пакет или коммит.

Полный прогон: **579 EditMode passed**, 0 failed/skipped/inconclusive,
Unity 6000.0.62f1 / Windows. Добавлено 21 регрессионное испытание относительно

## Настройки каналов, наборов и автозапуска

Подготовлен ProjectSettingsView: автозапуск/язык устройства, создание и
переименование каналов и наборов, независимый/FollowMain режим, подключение
наборов, выбор default и startup-наборов. Новый канал не подключает данные
неявно. Идентификаторы видимы read-only; переименование их не меняет.
Изменения проходят валидацию и Unity Undo/Redo. Удалить используемый набор
нельзя, а отключение источника или удаление канала не удаляет исходные файлы.

Источники подключаются по выбранному Resources-ассету или явному адресу
пользовательского провайдера. Resources проверяет существование, неоднозначность,
тип и валидность JSON. Повторное подключение того же адреса, включая различия
регистра Resources, отклоняется. Проверка адреса/типа не загружает содержимое
тяжёлой таблицы; пользовательский backend не подменяется Resources. Создание
пустого JSON использует ту же транзакцию. Источники другого backend пока
подключаются по контракту, их доступность должен проверять его Editor-reader.

UseForAutomaticStartup переносит новый проектный конфиг на фиксированный путь,
сохраняет GUID, ID и несохранённые настройки; JSON/ассеты остаются по прежним
адресам. Конфликт адреса и read-only/заблокированные файлы проверяются до нативных
операций Unity. Это явный перенос ассета, не мигратор старого типа и не запись
в историю локализационных правок. При ошибке выполняется возврат пути/настроек.

Полный прогон: **588 EditMode passed**, 0 failed/skipped/inconclusive,
Unity 6000.0.62f1 / Windows, чистая компиляция. Девять новых проверок покрывают
каналы, членство/default/startup наборов, ошибки источников, Undo, переход к
языкам внутри окна и перенос конфига. Локальный отчёт:
TestResults/Channels-C5/EditMode-project-settings-full.json.
Основное окно всё ещё требует переключения; текстовый UI, ассеты/оформление,

## Редактирование текста в выбранном канале/наборе

Подготовлен ProjectTranslationsView: виртуализированный список ключей с поиском,
редактирование одной записи по языкам, отдельные direct/fallback и источник,
переименование, регистрация внешних ключей, перенос и удаление. Операции используют
стабильный ID и LocalizationProjectEdit/Undo; новый ключ из JSON не регистрируется
молча. Неоднозначная внешняя запись отклоняется до изменения конфига.

Текст сохраняется явной кнопкой Save entry. Переключение записи предоставляет
Save/Cancel/Discard; Reload отказывается стирать набранный текст без явного
discard. Снимок байтов захватывается до отображения значений: внешняя правка
после открытия записи блокирует сохранение и оставляет введённый текст в поле.
Отсутствующий перевод не записывается автоматически в fallback-файл. При нескольких
возможных источниках пользователь выбирает место записи. Сбой не удаляет правки.

Добавлен ResetChanges в транзакцию: перед повторным сохранением изменения
пересобираются из текущих полей UI. Исходные байты при этом не перечитываются и
защита от внешнего изменения сохраняется. Это предотвращает запись отменённого
пользователем значения, оставшегося в черновике после предыдущего отказа.
Сброс также отбрасывает подготовленные новые источники/метаданные без записи.

Внешний Editor-reader можно передать для предпросмотра и регистрации метаданных.
При отсутствии writer поля текста недоступны для записи; не происходит скрытого
сохранения в Resources. Перенос между неоднозначными источниками пока сообщает
об ошибке; явное сопоставление адресов доступно в публичном MoveTextEntry API.

Подтверждённые точечные UI-проверки: 11 passed, включая 2500 записей с меньшим
числом созданных визуальных строк, поиск, fallback, сохранение/Undo, перенос,
внешние правки, регистрацию неоднозначного ключа, выбор источника и исправленный
повтор сохранения. Это не измерение производительности больших CSV или RAM.
Основное окно пока не подключено к виду; сохранность несохранённого UI-черновика
