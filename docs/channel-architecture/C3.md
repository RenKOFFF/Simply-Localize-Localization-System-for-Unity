# C3 — экземпляры и независимые каналы

## Модель состояния

`LocalizationRuntime` копирует определения конфига при создании. Копия содержит
строки, ID, адреса и правила связей; исходный ScriptableObject не становится
хранилищем языка игрока. Два runtime используют один конфиг и могут иметь
разные языки, активные наборы и подписчиков. Реестр провайдеров копирует
регистрации, но сознательно не клонирует пользовательские объекты провайдера.

`InitializeAsync` готовит стартовые наборы всех каналов. Main и FollowMain
получают выбранный язык Main; независимые каналы начинают со своих default.
Ошибка и отмена инициализации ничего не публикуют, частичный кандидат
освобождается, повтор допустим. Канал без активных наборов не загружает данные
или оформление.

`GetChannel` возвращает подготовленный снимок. `TryGetText`/`TryGetAsset` не
обращаются к провайдеру. Короткий поиск использует default-набор по ID, а поиск
через `LocalizationEntryReference` — замороженный индекс записей. Ответ содержит
запрошенный и фактический язык; недостающий русский ключ может вернуть английский
текст, сохранив `RequestedLanguage = ru`, `Language = en`.

## Смена языка

Main и следующие каналы — одна группа операции. Каждый независимый канал имеет
собственную группу, поэтому медленная загрузка голоса, следующего за Main, не
блокирует независимый канал. Произвольных цепочек следования нет.

Внутри группы одновременно подготавливается не более одного кандидата. Новый
запрос языка отменяет предыдущий; пока неотменяемый провайдер возвращает поздние
данные, новый кандидат ждёт очистки. Промежуточные отменённые запросы не начинают
I/O. Очередь ожиданий содержит задачи управления, а не дополнительные загруженные
состояния. Бессрочно зависший внешний провайдер продолжает удерживать свою
операцию; ложного успешного завершения или принудительного уничтожения нет.

Для всех участников сначала готовятся только активные наборы, fallback и
необходимое оформление. Затем их новые снимки публикуются вместе, без await
между заменами. Обработчик `Changed` видит согласованное состояние. Ошибка до
публикации сохраняет все прежние снимки. После публикации исключение подписчика
не откатывает состояние и не мешает остальным подписчикам; оно передаётся в
`ObserverError` (при отсутствии обработчика — в Unity Console).

Прямое переключение FollowMain запрещено. Если язык Main не входит в список
следующего канала, его цепочка начинается с собственного default, затем fallback.
Например, Main переключён на французский, а озвучка поддерживает en/ru: озвучка
выбирает en, сохраняя информацию о запросе fr. Неподдерживаемый язык независимого
канала отклоняется до отмены уже выполняющегося допустимого запроса.

`ReloadAsync` обновляет содержимое источников в рамках замороженных определений.
Повторный `SwitchLanguageAsync` на уже выбранный язык сохраняет снимок без
загрузки и событий. Он всё равно отменяет более раннее переключение и ждёт его
очистки; проверка выполняется после захвата группы. `ReloadAsync` принудительно
перечитывает источники даже при неизменном языке.
Чтобы принять редакторскую перестройку каналов/наборов/ID, нужно создать новый
runtime из нового конфига. Это явная граница; незаметной подмены метаданных
посреди загрузки нет.

## Подключаемые наборы и время жизни

`AcquireSetAsync(channelId, setId)` возвращает регистрацию активного набора.
Первый владелец загружает его, следующие увеличивают владение без повторного I/O.
Последний release удаляет набор из снимка без повторной загрузки остальных.
Стартовые наборы имеют собственную регистрацию до закрытия runtime.

Изменения набора сериализуются со сменой языка своей группы. Например, если
подключение уровня пришло во время смены en → ru, оно дождётся этой операции
и загрузит данные для уже опубликованного ru. Отмена или ошибка подключения не
оставляет скрытую регистрацию. Отключение ждёт уже начатую операцию, затем
удаляет свой набор. Независимые группы продолжают работать.

Лимиты числа записей и объёма текста проверяются для целого набора, включая
все его загруженные источники и fallback. Ограничение сырого JSON остаётся на
уровне источника. Эти лимиты не означают верхнюю границу памяти процесса.

Снимок принадлежит runtime до замены. `snapshot.Retain()` даёт отдельного
владельца: он может пережить смену языка и даже закрытие runtime. Это позволяет
закончить старую реплику. В текущей реализации такой владелец удерживает весь
снимок канала, включая его активные наборы, а не один клип. Для отдельного ассета
есть `LocalizationAssetValue.RetainSource()`: он удерживает только источник этой
записи и не удерживает другие таблицы/наборы канала. Гранулярность по-прежнему
определяется провайдером: для Resources это таблица со всеми её зависимостями.
Регрессия проверяет, что удерживаемая реплика не оставляет загруженной отдельную
таблицу изображений в том же канале.

После последнего владельца снимок очищает ссылки и освобождает источники C2.
`ReleaseAsync` runtime отменяет собственные операции и ждёт их drain, затем
освобождает своё владение. Отдельный владелец потребителя этим не уничтожается.
Повторный release возвращает ту же задачу. Ошибки подготовки и очистки остаются
различимыми; ошибка очистки старого снимка после успешной публикации поступает
в `ObserverError`, не выдаётся за отменённую смену языка.

Сессионные проверки запрещают старому runtime читать новое состояние после
сброса Play-сессии. Освобождение старого владельца не выгружает ресурсы новой.
Это дополнительно проверяется на настоящих Resources-клипах.

## Минимальное подключение

```csharp
var runtime = new LocalizationRuntime(projectConfig);
await runtime.InitializeAsync("ru", cancellationToken);

if (runtime.GetChannel().TryGetText("menu/play", out var value))
    label.text = value.Text;

await runtime.SwitchLanguageAsync("en", cancellationToken);

// Дополнительный набор, заранее доступный каналу в конфиге:
var level = await runtime.AcquireSetAsync(runtime.MainChannelId, levelSetId,
    cancellationToken);
// Завершение использования уровня:
await level.ReleaseAsync();
await runtime.ReleaseAsync();
```

В игре освобождение также выполняется при ошибках и закрытии потребителя.
Обычные UI-компоненты и глобальный фасад подключаются к этому движку в C4.
Конфиг и окно старого стенда на этом шаге ещё не заменены, второй постоянный
движок не является целевым состоянием. Форматирование и применение оформления
к компонентам также относятся к C4; загрузка оформления уже принадлежит снимку.

## Проверка

Windows / Unity 6000.0.62f1: **515 EditMode + 59 PlayMode passed**,
0 failed/skipped/inconclusive; компиляция без ошибок. Новые проверки:
26 EditMode для транзакций/конкуренции/наборов/границ ошибок и 4 PlayMode
для настоящих Resources, общих владельцев, выборочного удержания источника
и границы сессий. Полные локальные результаты —
`TestResults/Channels-C3/EditMode-full.json` и `PlayMode-full.json`, вне Git.

Освобождение проверяется по отсутствию прежнего Instance ID среди живых объектов
соответствующего типа. Сравнение сохранённой C#-обёртки с null не используется
как доказательство освобождения. Эти проверки не измеряют память процесса/GPU
и не заменяют приёмку C9. Player и остальные платформы этим прогоном не проверены.
