# C4 — публичное подключение

Этап выполнен: фасад, bootstrap, компоненты, стенд и проверки используют один
движок каналов. Старые Manager/Context/Prepare и прежние runtime-провайдеры
удалены. Ниже сохранена история промежуточных проверок; актуальный итог находится
в разделе «Единственный движок». Окно C5 и приёмка C6–C9 ещё не завершены,
поэтому это состояние разработки, не готовый релиз.

## Уже подготовлено

`LocalizationRuntime.Get` / `Format` читают только подготовленные данные,
используют тот же парсер и форматирующее ядро, что существующая реализация.
Поддерживаются индексированные/именованные параметры, plural, FormSelector,
экранирование фигурных скобок и устойчивое поведение некорректных шаблонов.
Есть поиск по каналу/набору и стабильной ссылке записи.

Пустой текст сохраняет прежнее поведение fallback: ищется следующий непустой
перевод. Если ничего не найдено, возвращается буквальный ключ. Отсутствующий
ключ с `{0}` не рассматривается как шаблон и не подставляет параметры в путь.

`LocalizationMessageFormatter` содержит отдельный ограниченный FIFO-кэш
шаблонов. По умолчанию его предел берётся из `MaxTemplates`; пользовательский
форматтер может иметь собственную политику. Закрытие runtime очищает его
собственный кэш; явно переданный форматтер остаётся во владении вызывающего.
`ILocalizationTextFormatter`
реализуется в скрипте игры без форка и получает текст вместе с фактическим и
запрошенным языком. Он также обязан соблюдать запрет скрытого I/O при чтении.

Plural всегда определяется языком найденного текста. Культура чисел/дат
явная: `ResolvedLanguage` по умолчанию, `RequestedLanguage` либо `Invariant`.
Например, при ru → en fallback шаблон `"{0} {0|coin|coins}"` с 1.5 даёт:

- ResolvedLanguage: `1.5 coins`;
- RequestedLanguage: `1,5 coins`;
- Invariant: `1.5 coins`.

Выбор культуры не меняет plural английского шаблона. Если .NET не знает
культуру пользовательского языкового кода, используется invariant culture,
без неявной зависимости от языка ОС. Это политика нового runtime; при переходе
нужно явно выбрать RequestedLanguage, если интерфейс игры должен форматировать
числа по запрошенному языку даже внутри fallback-текста.

`LocalizationPluralRules` хранит регистрации конкретного набора правил.
Форматтер копирует эти регистрации при создании. Поздняя правка исходного
набора или старых глобальных overrides не меняет работающий runtime.
Объекты custom-правил не клонируются: если игра намеренно передаёт изменяемый
объект нескольким форматтерам, за его совместное использование отвечает игра.

```csharp
var rules = new LocalizationPluralRules();
rules.Register("x-my-game", new MyPluralRule());
var formatter = new LocalizationMessageFormatter(
    pluralRules: rules,
    valueCulture: LocalizationValueCulture.ResolvedLanguage);
var runtime = new LocalizationRuntime(config, formatter: formatter);
await runtime.InitializeAsync("ru");
string label = runtime.Get("coins", 21);
```

Валидация конфигурации теперь проверяет встроенные правила либо явно переданный
набор `config.Validate(rules)`. Старые глобальные overrides не могут скрыть
предупреждение для нового runtime, который их не использует. Без явно переданных
правил редактор не утверждает, что внешний код зарегистрировал custom-правило.

`GetAsset<T>` и типизированный `TryGetAsset<T>` ищут подходящий тип по подготовленной
fallback-цепочке. Неподходящий тип в текущем языке не заслоняет подходящий объект
fallback-языка. `RetainSource` удерживает именно источник найденного объекта.

`ProfileApplier` принимает `LocalizationAppearance`: TMP, legacy Text, baseline,
типографика, spacing, layout и общие временные шрифты обслуживаются одним кодом.
Старый `LanguageProfile` временно наследует эти поля, сохраняя их сериализованные
имена; runtime каналов не использует его идентичность и fallback-поля.
Это промежуточное состояние редакторского перехода, не новый рекомендуемый
формат данных или автоматический мигратор.
Производный класс оформления может переопределить `GetLocalizationDependencies`,
перечисляя дополнительные Unity-объекты вместе с зависимостями базового класса.
Так учёт владения остаётся расширяемым из скриптов игры.

`RetainAppearance` позволяет потребителю удержать загруженное оформление
отдельно от таблиц текста/голоса. Перед release потребитель должен отсоединить
шрифты и уничтожить заимствующие их временные варианты. Компоненты теперь
выполняют эту последовательность при перепривязке, отключении и закрытии runtime.

## Обязательная оставшаяся работа C4

1. Удалить оставшиеся прямые зависимости от старого runtime. Перевести важные
   регрессии на новые публичные API. Удалить старые
   менеджер/контекст/подготовленные данные и старый runtime-загрузчик, сохранив
   алгоритмическое покрытие, а не второй исполняемый движок ради тестов.
2. Проверки владения настоящими Owned-ресурсами на компонентах и две Play-сессии
   без Domain Reload и Scene Reload одновременно добавлены. Их вместе с остальными
   регрессиями повторять при последующем удалении старого движка. Уже проверены
   внешний компонент, независимые каналы, два экземпляра, fallback-оформление,
   TMP/legacy/изображения/аудио, включение и закрытие.
3. Завершить инструкцию замен API. Основная переделка окна и явная перестройка
   данных стенда остаются C5/C6; временные ошибки старого конфига должны быть
   понятными и не запускать скрытую совместимую копию старого движка.

## Подключение фасада и компонентов

`Localization.InitializeAsync(config, providers: registry)` готовит кандидат
до замены текущего runtime. Ошибка оставляет прежние данные. Новый запрос отменяет
старый, но дожидается очистки его позднего результата. `ShutdownAsync` отсоединяет
фасад и компоненты, отменяет подготовку и дожидается её завершения. Повторная
инициализация из события не передаёт bootstrap владение чужим экземпляром.

Автозапуск читает только `LocalizationProjectConfig` по фиксированному адресу
`Resources/SimplyLocalizeSettings.asset`. Флаг `AutoInitialize` учитывается
автозапуском; явный вызов инициализации не зависит от этого флага. Старый тип
конфига не конвертируется и не запускает второй движок. Окно Setup ещё требует
перехода C5; существующие сцены/данные будут перенастроены в C6/C8.

`ReplaceProvidersAsync` подготавливает все активные наборы всех каналов с новой
регистрацией источников. Языки независимых каналов и регистрации наборов
сохраняются. Публикация общая; ошибка сохраняет и данные, и прежние провайдеры.
Во время замены смена языка ожидает освобождения соответствующей группы.

Компоненты используют Main и default-набор по умолчанию. Для явного экземпляра:

```csharp
label.Bind(runtime, channelId, setId);
label.Key = "menu.play";
// Либо стабильная ссылка записи; она имеет приоритет над Key/SetId:
label.Entry = new LocalizationEntryReference(channelId, entryId);
// Возврат к глобальному фасаду:
label.UseDefaultRuntime();
```

Привязка и Refresh не загружают данные. Набор должен входить в стартовые или
удерживаться игровым кодом через `AcquireSetAsync`. `Bind(null)` явно отсоединяет
компонент. Его `ReleaseCompletion` позволяет дождаться собственной очистки.
`LocalizedAsset<T>` расширяется в сборке игры через `ReadCurrentAsset` и
`ApplyAsset`; `RestoreAsset` переопределяется при особом восстановлении исходного
значения. Аудиокомпонент останавливает воспроизведение до смены/отсоединения клипа.

Текст и override используют язык фактически найденного текста; standalone
override и `LocalizedEvent` — разрешённый язык своего канала. Ссылки на
`LanguageProfile` в записях overrides/events заменены строкой `languageCode`.
Поле override-языка bootstrap также теперь строковое. Старые сериализованные
привязки необходимо явно перенастроить, а не оставлять видимость совместимости.

| Старый вызов | Замена |
|---|---|
| `Initialize`, `SetLanguage`, `Reload`, `Shutdown` | Соответствующий метод с `Async`, ожидать Task |
| `Localization.Manager` | `Localization.Runtime` |
| `LocalizationManager` / `LocalizationContext` | `LocalizationRuntime`, один экземпляр на изолированное состояние |
| `PrepareLanguage` / `ApplyPreparedLanguage` / `PreparedLocalizationData` | Ожидать `InitializeAsync` / `SwitchLanguageAsync`; публикация выполняется атомарно внутри runtime |
| `ResourcesDataProvider` / `ScopedResourcesDataProvider` / `ResourcesLanguageSources` | `ResourcesLocalizationSourceProvider`, точные `LocalizationSourceReference` в определениях наборов |
| `ILocalizationDataProvider` / `IAsyncLocalizationDataProvider` | `ILocalizationSourceProvider` и возвращаемый `LocalizationSourceLease`; провайдер остаётся собственностью вызывающего |
| `LocalizationContextOptions` | `LocalizationRuntimeOptions`; поля лимитов и владения сохранены |
| `SetDataProvider` | `LocalizationSourceRegistry` + `ReplaceProvidersAsync` |
| `OnProfileChanged` / `CurrentProfile` | События runtime, результат текста и `GetAppearance(language)`; для компонентов это автоматизировано |
| Настройки статического info-лога из старого конфига | Явные `LocalizationLogger.Enabled` / `EnabledInBuild` |

Информационные сообщения статического логгера отключены по умолчанию. Ошибки
наблюдателей runtime доступны через `ObserverError`, для глобального фасада —
через `OnError`. Ошибки операций остаются в Task. Без обработчика ошибки
наблюдателей выводятся в Unity Console. Публичные статические подписки сбрасываются
между Play-сессиями; внутренние привязки компонентов переживают режим без перезагрузки.

При переносе прежних регрессий выявлено отсутствие адреса файла в ошибке разбора
JSON нового Resources-провайдера. Сообщение теперь содержит точный адрес и
сохраняет исходное исключение в `InnerException`.

Bootstrap также дожидается уже начатого автоматического поиска. Если поиск
закончился без конфига, bootstrap запускает свой. Если другой инициализатор
опубликовал runtime, bootstrap остаётся без владения и не выключает его при
уничтожении. Ошибка уже начатой чужой инициализации не запускает скрытый повтор.

## Перенос регрессий на единственный будущий runtime

Проверки прежних Context/Prepare/Loading/ScopedResources теперь используют
каналы и источники. [Карта покрытия](C4-COVERAGE.md) связывает старые гарантии
с новыми проверками и явно перечисляет изменённые контракты. Проверка редакторского
предпросмотра будет восстановлена при переходе окна в C5; она не считается
проверенной через старый редактор и новый runtime.

`LocalizationContextOptions` переименован в `LocalizationRuntimeOptions` без
дублирующего класса; поля и значения по умолчанию сохранены. Это обычные C#-опции,
не сериализованный проектный конфиг. Оставшиеся вызовы стенда обновлены только
для компиляции — архитектура стенда этим не исправлена.

Исправлена лишняя подготовка при выборе уже текущего языка: готовый снимок,
владельцы и события остаются прежними. Более ранний незавершённый запрос всё равно
отменяется и очищается. Для повторного чтения данных есть `ReloadAsync`, включая
перезагрузку группы Main/FollowMain через её участника.

Нативные PlayMode-проверки подтверждают порядок: AudioSource останавливается
и отсоединяет клип, TMP восстанавливает исходный шрифт, затем освобождается
Owned-источник. Фикстура оформления здесь проверяет владение, а не рендеринг глифов.
Дополнительный EditMode-сценарий проверяет две Play-сессии с обоими отключёнными
reload-параметрами и восстановление привязки компонента к новому runtime.

## Единственный движок

Удалены LocalizationManager, LocalizationContext, PreparedLocalizationData,
IAsyncLocalizationDataProvider, ScopedResourcesDataProvider и ResourcesLanguageSources.
Новый runtime не зависит от прежнего LocalizationConfig. Общая проверка адреса
Resources находится в LocalizationResourceAddress; точный runtime-адрес не допускает
пустое значение или завершающий `/`, редакторский поиск папок задаётся явно.

Прежний синхронный читатель папок и его интерфейс перенесены в сборку Editor как
EditorResourcesDataSource / IEditorLocalizationDataSource. Они временно обслуживают
старые Coverage/авторинг до C5 и не входят в Player. Это не альтернативный runtime
и не рекомендуемый способ загрузки игры. LocalizationConfig и LanguageProfile
ещё нужны старым редакторским данным; это не поддержка старого исполняемого API.

Night Shift и его Player-проверки используют LocalizationRuntime. Один конфиг
содержит Main/Common и независимые Voice/Visuals; мир удерживает регистрации
наборов, а не отдельные контексты. Этот необходимый для удаления движка участок
данных C6 описан отдельно в [C6.md](C6.md). Полный переход UI стенда остаётся C8.

Проверено на Unity 6000.0.62f1 / Windows: 525 EditMode и 73 PlayMode passed,
0 failed/skipped/inconclusive. Последующая компиляция чистая. Windows x64 Release
собран: 0 ошибок, 0 предупреждений, 117365771 байт. Локальные отчёты
EditMode-single-engine.json / PlayMode-single-engine.json находятся в
TestResults/Channels-C4; build.txt — в TestResults/Channels-C6. Сборка и тесты
не доказывают производительность или поддержку других платформ; это приёмка C9.
