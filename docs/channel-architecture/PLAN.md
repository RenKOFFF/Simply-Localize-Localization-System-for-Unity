# Один конфиг и независимые каналы

Работа начата 17 ноября 2026 года. Итоговое устройство демонстрационной игры описано в [C8](C8.md), результаты проверок и границы совместимости — в [C9](C9.md).
План продолжает стабилизацию после этапа 9; это отдельная нумерация C0–C9.
Старый этап 10 (массовый CSV и оптимизации) не запускается автоматически.

## Цель и границы

Один конфиг описывает локализацию проекта. Независимые каналы выбирают язык,
наборы контента определяют нужные данные, владельцы загрузок — время их жизни,
провайдеры — способ получения. Архитектура не зависит от жанра, сцен Night Shift
или числа игроков. Простой проект использует Main/Common без обязательного
ручного управления каналами. Большой проект явно подключает наборы и провайдеры.

Конфиг не хранит состояние игрока и не собирает прямые ссылки на все тяжёлые
ресурсы. Один конфиг не означает один JSON, одну таблицу или один бандл.
Несколько изолированных runtime-экземпляров могут использовать один конфиг.
Настройка ведётся в окне Simply Localize; Inspector — дополнительный путь.
Скриптовый Editor API и runtime-расширения работают без форка пакета.

Автоматический мигратор и параллельный legacy-движок не разрабатываются.
Существующие переводы переиспользуются там, где формат позволяет; конфиги и
привязки стенда перенастраиваются явно. Несовместимые изменения документируются
с короткими шагами обновления. Старые данные не удаляются до проверки ссылок.
Resources остаётся встроенным провайдером. Addressables, CDN, файловые пакеты
модов и полный процесс работы переводческой команды — отдельные будущие задачи.

- Запустить исходные EditMode/PlayMode; отдельно записать ограничения проверки.
- Убрать зависимости регрессий ядра от игровых ресурсов Night Shift.

- Составить карту уникальных сценариев маленького стенда до его удаления.

  на Windows / Unity 6000.0.62f1. Три ресурсных набора тестов отделены от демо,

### C1 — модель конфигурации и валидация (выполнен)

- Один проектный конфиг: языки, каналы, наборы, описания источников, автозапуск.
- Стабильные ID отдельно от отображаемых названий и адресов хранения.
- Профиль языка разделить на идентичность/правила и подключаемое оформление.
  Не удерживать все шрифты через корневой конфиг.
- Independent и FollowMain; никаких произвольных цепочек следования на старте.
- Default/fallback выбираются из доступных языков соответствующего канала;
  fallback не должен образовывать цикл. Общий каталог не доказывает доступность.
- Статус plural-правила доступен для валидации и будущего окна C5.
- Проверки: дубликаты ID, переименование, перенос, удаление, пустой конфиг,
  циклы, неверные источники, неизвестный plural, региональные и custom-правила,
  отсутствие прямых тяжёлых зависимостей у стартового конфига.
- Результат: новая модель, единая runtime/Editor-канонизация кодов, индекс
  идентичностей, статус plural, отдельное оформление по адресу. 478 EditMode +
  45 PlayMode passed на Unity 6000.0.62f1. [Контракты и границы C1](C1.md).

### C2 — провайдеры и владение (выполнен)

- Общий контракт async-загрузки и освобождения, расширяемый из проекта игры.
- Явная единица загрузки и сведения о поддерживаемых возможностях провайдера.
- Resources реализует этот контракт и честно описывает загрузку прямых
  зависимостей таблицы. Наличие интерфейса не выдаётся за поштучную загрузку.
- Shared/Owned/Borrowed, удержание ожидающих загрузок, отмена и поздние результаты.
- Проверки: два владельца, общий fallback, разные источники/экземпляры,
  последний release, ошибка, отмена, повтор, изоляция сессий и пользовательский
  провайдер. Запрос одного ассета из большой таблицы и отдельные метаданные.
- Addressables и файловый пакет здесь не реализуются.
- Результат: расширяемые источники, отдельные метаданные по возможности,
  удерживаемые владельцы и точный Resources-провайдер с общим нативным учётом.
  489 EditMode + 55 PlayMode passed на Unity 6000.0.62f1.
  [Контракт, пример и ограничения C2](C2.md).

### C3 — runtime-экземпляры и каналы (выполнен)

- Неизменяемая конфигурация отделена от состояния экземпляра.
- Смена языка готовит только активные наборы затронутых каналов, затем применяет
  согласованное состояние. Ошибка/отмена сохраняет прежнее.
- Независимый канал не включается в чужую операцию неявно. Связанные каналы
  публикуются вместе; события получают уже согласованное состояние.
- Устаревший запрос не может примениться после нового; Release дожидается
  завершения собственной очистки. Правила описаны в CONTRACTS.md.
- Проверки: независимые и связанные каналы, частичный отказ, отмена/повтор,
  освобождение во время загрузки, медленный источник, два игрока, два runtime,
  общий источник и неподдерживаемый язык.
- Результат: замороженные определения, независимые экземпляры, атомарные группы
  Main/FollowMain, сериализация регистрации наборов, удержание снимка или одного
  источника ассета, отмена и drain. 515 EditMode + 59 PlayMode passed.
  [Контракты и ограничения C3](C3.md).

### C4 — публичный API и компоненты (выполнен)

Фасад, компоненты, стенд и регрессии используют runtime каналов. Прежние
менеджер, контекст, Prepare/Apply и runtime-провайдеры удалены. Полные прогоны:
525 EditMode + 73 PlayMode, без ошибок/пропусков. Windows Player собран без
ошибок/предупреждений. Новое окно и общая приёмка остаются этапами C5–C9.
[API, история проверок и ограничения](C4.md).

- Глобальный фасад делегирует одному экземпляру; единственный движок состояния.
- Async-инициализация/переключение; синхронное чтение только готового состояния
  без скрытого I/O. Удалить блокирующие обходы, а не поддерживать два движка.
- Компоненты выбирают канал/набор (Main/Common по умолчанию), поддерживают явную
  привязку runtime. Профили/шрифты применяются общей системой.
- Перечень замен старых API и понятные ошибки для старой конфигурации.
- Проверки: TMP/legacy Text/изображения/аудио, fallback-язык результата,
  повторное включение, уничтожение, отсутствие чтений провайдера в ready-пути,
  пользовательский компонент без форка, события без влияния соседнего runtime.

### C5 — окно Simply Localize

Статус: завершён. Окно, Inspector компонентов, поля ссылок и скриптовая настройка
используют LocalizationProjectConfig, каналы/наборы и стабильные EntryId.

Работают точные источники, внешние readers, редакторские транзакции текста,
ассетов и оформления, заметки по ID, CSV и Auto-Localize с preview/apply/rollback.
Save/Cancel/Discard защищают переходы и закрытие; незавершённые правки переживают
domain reload. Diagnostics показывает владельцев/источники без обещания точной RAM.
Старые вкладки, setup, CSV, data/coverage/rename utilities удалены. Замены Editor API
описаны в журнале; второй legacy-движок и автоматический мигратор не добавлены.

Исправлены C5-I02–I11: кодировки и JSON, новые пути, startup build hook, отложенное
Undo, локальные Game View prefs, извлечение Spine и компоновка короткого окна.
Оба Spine Inspector используют каналы и EntryId. Старые LocalizationConfig/
LanguageProfile выведены из создания и редактирования; только сериализованные
контейнеры остаются до очистки 10 ссылающихся на них .asset в C6.

Приёмка: **830/830 EditMode passed**, 0 failed/skipped/inconclusive, 164.03 s,
Unity 6000.0.62f1 / Windows / D3D11. Полный запуск выполнен в изолированной копии
на отдельном невидимом desktop, без перехвата пользовательского фокуса.
Отдельно **20/20 Spine Editor passed** с настоящим Spine 4.2.121.
Проверены снимки всех страниц при 1100×780 и 700×450; layout-тест дополнительно
проверяет достижимость действий при минимальном размере 700×400.
Поведение игрового runtime в этом финальном блоке не менялось; последний полный PlayMode
остаётся 73 из C4. Рендеринг/skin lifecycle Spine и матрица других платформ
относятся к дальнейшей приёмке. C6–C9 не продолжались.
История реализации, отчёты, замены API и ограничения: [C5.md](C5.md).

Согласованные требования этапа сохраняются:

- Setup, Languages, Translations, Assets, Coverage, Tools и Diagnostics работают
  с одной моделью. Каналы и наборы появляются по мере необходимости.
- Выбор языка, default/fallback из выбранных; статус plural и доступности данных.
- Переименование/перенос/CSV сохраняют идентичность; конфликт не перезаписывает
  чужую запись. Правки внешнего JSON требуют обновления актуального состояния.
- Разделить редакторский выбор и язык запущенной игры. Сохранить скриптовый путь
  настройки и внешние расширения Editor; замены старых API документировать.
- Diagnostics: кто использует ресурс, что система отпустила, что известно о
  физической памяти. Снимки не удерживают Unity-объекты.
- Проверки: Undo/Redo, dirty/reload, внешняя правка, preview/apply/rollback,
  каналы/наборы с одинаковыми локальными ключами, неизвестный plural,
  масштабы окна и читаемость, зависимости ресурсов и необоснованные обещания RAM.

### C9 — приёмка архитектуры (выполнен в описанной матрице)

- Маленький проект; независимая озвучка; большие наборы; два игрока;
  пользовательский провайдер; Play с Domain Reload и без него.
- Чистый UPM/Git-проект, заявленная матрица Unity и целевых платформ;
  отмечать непроверенные конфигурации. Тесты/генераторы не входят в UPM.
- Сценарий памяти: одинаковые данные, старт → набор → смена языка → release,
  повтор не менее 20 циклов. Отдельно фиксировать старое/новое/fallback,
  число владельцев, peak/settled, managed/native и стоимость главного потока.
  Профилировщик подтверждает память; снимок реестра не заменяет измерение.
- Производительность конкурентов сравнивать лишь при одинаковой нагрузке и
  окружении. Это не автоматический запуск старого этапа 10 с 100 000 CSV-ключей.
- Выход: проверяемый отчёт, список оставшихся ограничений, инструкция обновления.
- Перед закрытием проверить и устранить C5-I01: небезопасное выделение массива
  по большому индексу параметра в runtime. Editor-защита не заменяет эту проверку.

## Порядок коммитов и хранения

Текущая ветка dev/localization-stability. Каждый завершённый шаг — отдельный
проверенный коммит; объединение при выпуске возможно позже без потери локальной
истории разработки. Не включать чужие изменения ProjectSettings, временные
результаты, логи, снимки и сборки. Нужные повторяемые фикстуры/тесты сохранять
в playgrounds, документацию — вне src/SimplyLocalize.

Автоматические прогоны выполнять в изолированной фоновой копии проекта.
Не использовать рабочий редактор пользователя для тестов с ShowUtility/Focus
и не переключать фокус его экрана ради снимков или проверки компоновки.

Полное покрытие CLDR, псевдолокализация, статусы устаревшего перевода, XLIFF,
Google Sheets и доставка языковых пакетов остаются отдельными предложениями.
Переход на каналы не должен превращаться в неограниченное расширение объёма.
