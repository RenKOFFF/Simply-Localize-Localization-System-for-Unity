# C2 — источники и владение ресурсами

## Реализованная граница

`ILocalizationSourceProvider` загружает один источник асинхронно и возвращает
`LocalizationSourceLease`: данные плюс обязанность их освобождения. Интерфейс
реализуется обычным скриптом игры, без изменения пакета. Реестр провайдеров
`LocalizationSourceRegistry` принадлежит экземпляру; его копия фиксирует
регистрации, но не клонирует пользовательские объекты провайдеров. Общий кэш
между такими объектами не возникает автоматически.

Запрос фиксирует адрес, язык, выбранные ключи, лимиты, владельца и сессию.
Контейнеры результата копируются и доступны только для чтения. Unity-объекты
остаются объектами Unity: контейнер не делает их содержимое неизменяемым.

Провайдер объявляет единицу загрузки (`ContentSet`, `Table`, `Asset`), наличие
прямых зависимостей и возможность отменить само I/O. Дополнительный интерфейс
`ILocalizationSourceMetadataProvider` позволяет читать список ключей отдельно
от тяжёлого содержимого. Это возможность конкретного провайдера, не обещание
всем источникам. Тестовый внешний провайдер читает метаданные без создания
текстур и создаёт только один запрошенный объект.

## Resources

Встроенный провайдер загружает точный адрес, без сканирования папок:

- JSON — таблица текста; ограничения размера проверяются до разбора, числа
  записей и объёма текста — до фильтрации выбранных ключей.
- `LocalizationAssetTable` — таблица и её прямые зависимости. Запрос одного
  ключа фильтрует результат, но не предотвращает загрузку остальных зависимостей.
- `LocalizationAppearance` — оформление со шрифтами. Учитываются TMP-материал,
  атласы, исходный шрифт и цепочка fallback-шрифтов, включая циклические ссылки.

У Resources нет отдельного чтения метаданных этих таблиц и отмены нативного
`LoadAsync`. Отмена ждёт поздний результат, учитывает его владение и освобождает
свой экземпляр до завершения задачи. Аудио при включённом `PrepareAudio` готово
до возвращения результата, как в существующем контексте.

`SourceEntryCount` показывает число записей до фильтрации. Это не измерение RAM.
Тестовая таблица содержит 64 ключа, но лишь четыре повторно используемых клипа:
тест доказывает гранулярность и владение, а не масштабируемость больших записей.

## Владельцы, отмена и ошибки

Каждая успешная загрузка возвращает одного владельца. `Retain()` создаёт ещё
одного; освобождение первого не уничтожает данные второго. Последний
`ReleaseAsync()` ждёт callback провайдера. Повторный и реентерабельный release
возвращают ту же задачу. Ошибка callback остаётся видимой вызывающему.

Реестр освобождает поздний отменённый, неверного типа и превышающий лимиты
результат. Если провайдер сам падает до возврата lease, он обязан очистить свою
частично выполненную загрузку. Ошибка очистки не замалчивается. Бессрочно
зависший пользовательский провайдер не превращается в успешное освобождение.

Все операции принадлежат потоку Unity. Доступ к данным/Retain после release
или смены Play-сессии запрещён. Старый Resources-владелец не освобождает данные
новой сессии. Пользовательский провайдер получает `SessionId` и обязан учитывать
его в собственном кэше и callback освобождения; реестр не может исправлять
произвольные глобальные кэши внешнего кода.

Resources использует общий существующий учёт нативных объектов даже между
разными экземплярами провайдера и разными таблицами. Borrowed-владелец удерживает
объект до своего release; только заимствованный объект система не выгружает.
Если этот же объект был передан в Owned, он выгружается после последнего
учтённого пользователя. Внешние ссылки, не участвующие во владении, неизвестны
системе. Потребитель должен отсоединить их до освобождения Owned.

Prefab/Component/AssetBundle остаются только Borrowed: `Resources.UnloadAsset`
не даёт корректного общего способа освобождения таких объектов. Произвольные
зависимости пользовательских SO объявляются через `ILocalizationAssetDependencies`;
универсального сканирования всех ссылок, материалов или сцен нет.

## Пример

```csharp
var sources = new LocalizationSourceRegistry();
var request = new LocalizationSourceRequest(
    new LocalizationSourceReference("resources", "Localization/en/Voice",
        LocalizationSourceKind.AssetTable),
    "en",
    requestedKeys: new[] { "greeting" },
    options: new LocalizationContextOptions {
        Ownership = LocalizationResourceOwnership.Owned
    });

var owner = await sources.LoadAsync(request, cancellationToken);
var playingLine = owner.Retain();
audioSource.clip = (AudioClip)playingLine.Data.Assets["greeting"];
audioSource.Play();
await owner.ReleaseAsync(); // Реплика ещё удерживает источник.

// Когда игра закончила или прервала реплику:
audioSource.Stop();
audioSource.clip = null;
await playingLine.ReleaseAsync();
```

В реальном потребителе release должен выполняться также при ошибке/отключении
объекта. Этот пример поясняет низкоуровневый контракт. Обычные компоненты получат
подключение через runtime каналов в C3–C4; это не требование вручную писать
загрузчик для каждой надписи.
