# Контракты C0

Это проектные решения для C1–C9, не описание уже существующих публичных типов.
Реализация должна иметь один путь исполнения; временные заглушки нового API
и второй legacy-движок не нужны. Новое поведение проверяется на независимых
фикстурах, старые регрессии сохраняют смысл, а не устаревшие сигнатуры.

## Идентичность и адреса

Язык имеет канонический языковой код. Канал, набор и запись имеют постоянный
непустой ID; отображаемые имена, ключи и адрес провайдера ID не заменяют.
Ключ уникален внутри набора. В C1 вводится типизированная ссылка на запись:
ID записи + канал использования; набор определяется индексом конфигурации.
Строковый путь канал/набор/ключ остаётся удобным адресом поиска, не обещанием
устойчивости к произвольной реорганизации.

- Переименование сохраняет ID и сериализованные ссылки по ID.
- Перенос записи в другой набор сохраняет ID. Если набор недоступен выбранному
  каналу, валидация сообщает конфликт; другой канал не выбирается молча.
- Загруженный снимок не меняется из-за правки редакторского индекса; изменение
  маршрутизации становится доступно после явной подготовки/Reload.
- Удаление оставляет обнаружимую неразрешённую ссылку. Новая запись с тем же
  ключом не получает ID удалённой записи автоматически.
- Переводы одной записи на разные языки используют один ID. Разные записи с
  одинаковым коротким ключом не объединяются автоматически.
- CSV/внешний источник может содержать ID; импорт без ID сопоставляется с
  существующим набором/ключом, новые ID назначаются до применения плана.
  Неоднозначное сопоставление требует решения, а не тихой перезаписи.
- ID-индекс — лёгкие метаданные. Unity GUID ассета не является ID перевода.
  Точный сериализованный формат выбирается в C1 с тестами round-trip/конфликтов;
  не добавлять обязательный скрытый файл с полной копией переводов.

## Состояние и выбор языка

Конфиг содержит определения, runtime — выбранные языки, операции и владельцев.
Каталог языков проекта общий; доступные языки и fallback определяются каналом.
Main/Common обслуживает простой проект. Каналы произвольны по назначению:
тип Text/Voice/Images не зашивается в ядро. FollowMain — прямая связь с Main,
без графа взаимного следования в первой реализации.

Два runtime используют один конфиг без общих изменяемых языков/событий. Общий
ресурс может разделяться только с корректным ключом источника и учётом владельцев.
Глобальные plural-override/логирование/сессионный reset требуют отдельной проверки:
static API не должен скрыто ломать изоляцию экземпляров. Immutable правила можно
разделять; изменяемые override принадлежат явно определённому уровню.

Результат поиска содержит запрошенный и фактический язык. Plural использует
язык найденного шаблона. Политика культуры чисел/дат и оформление fallback
фиксируются отдельно в C1/C4; нельзя выводить их неявно из глобальной локали.
Добавление языка не гарантирует встроенные plural-правила, glyph coverage,
shaping или правильную смешанную RTL/LTR-разметку.

## Переключение и конкуренция

1. Зафиксировать участников операции и активные наборы. Независимые каналы
   остаются в своём состоянии; Main захватывает только следующие за ним каналы.
2. Подготовить кандидата через провайдеры, fallback и готовность ресурсов.
3. Проверить поколение операции, отмену и лимиты до публикации.
4. Опубликовать участников вместе, затем уведомить потребителей. Обработчик
   события должен видеть полностью применённое состояние участников.
5. Отпустить старое владение после отсоединения/завершения его потребителей.

Ошибка любого обязательного участника до публикации сохраняет прежнее состояние
всех участников. Ошибка пользовательского обработчика после публикации не является
ошибкой подготовки и не откатывает уже увиденное другими обработчиками состояние.
Старый запрос не может перезаписать новый (поколение/версия), даже если источник
не умеет отменять I/O. Его поздний результат освобождается по правилам провайдера.
Отмена одного владельца не отменяет загрузку, нужную другому.

Подключение/отключение наборов во время подготовки должно сериализоваться либо
инвалидировать кандидата; публиковать его для устаревшего списка владельцев нельзя.
Контракт проверяется в C3. Не вводить неограниченную очередь кандидатов.
Release идемпотентен и ждёт собственного drain; бессрочно зависший внешний
провайдер не превращается в ложное успешное завершение. Отмена/таймаут означают
окончание ожидания вызывающего, но не доказательство физического освобождения.

## Гранулярность, владение и память

Провайдер объявляет фактическую единицу загрузки: набор, таблица или ассет.
Лёгкие метаданные и тяжёлое содержимое раздельны там, где это поддержано.
Для Resources-таблиц с прямыми ссылками честно сохраняется уровень таблицы:
интерфейс LoadAsset сам по себе не делает её зависимости ленивыми.

Канал не является бандлом. Набор — логическая группа, провайдер может отображать
её на файлы, таблицы или бандлы. Размер файла, число записей и RAM — разные меры.
Счётчик владельцев не знает произвольные ссылки из пользовательского кода.
Borrowed не уничтожается системой; Owned требует соблюдения контракта потребителя.
Повторный release не уменьшает владение другого потребителя.

Смена языка временно удерживает старый и новый наборы плюс fallback и продолжающих
работу потребителей. Лимиты записей/JSON не являются жёстким ограничением native RAM.
Для голоса игра решает, закончить старую реплику или прервать: канал не управляет
сценарием воспроизведения. Публичный lease удерживает нужный ресурс до завершения.

Диагностика различает: ресурс удерживается; система отпустила владение; провайдер
сообщил об освобождении; физическая память не подтверждена. Даже вызов UnloadAsset
не является замером всей памяти зависимостей. Снимки содержат идентификаторы и
значения, а не ссылки, удерживающие UnityEngine.Object.

## Границы продукта и стенда

Публичные интерфейсы провайдера, форматирования, привязок и Editor-команд доступны
проекту игры. Ядро не знает сцен, миров, префиксов PlayerPrefs и метрик Night Shift.
Демо использует те же публичные API, что и сторонняя игра. Автоматизация,
генераторы, fault injection и тесты не входят в устанавливаемый UPM-пакет.

Основное окно объясняет простые действия обычными словами; расширенные настройки
доступны по необходимости. Inspector показывает служебные данные read-only,
вместо скрытия состояния. Редакторский выбор языка не переключает игру неявно.

## Основания сравнения

Unity поддерживает LocaleOverride и ссылки Table GUID/Entry ID:
https://docs.unity3d.com/Packages/com.unity.localization@1.5/api/UnityEngine.Localization.LocalizedReference.html
Unity загружает запрошенные ассеты через Asset Tables:
https://docs.unity3d.com/Packages/com.unity.localization@1.5/manual/AssetTables.html
Собственные источники поддерживаются и Unity:
https://docs.unity3d.com/Packages/com.unity.localization@1.5/manual/Scripting.html
I2 разделяет данные языков и загружает их по необходимости:
https://www.inter-illusion.com/assets/I2LocalizationManual/MemoryUsage.html
Lean также имеет варианты ленивой загрузки CSV:
https://carloswilkes.com/Documentation/LeanLocalization

Каналы/владение/диагностика оцениваются по удобству и проверяемому поведению.
Утверждений «конкурент не умеет независимые языки», «все языки всегда в RAM»
или «Simply быстрее» эти документы не обосновывают.
