# C1 — модель проектной конфигурации

Выполнен 2026-11-17 поверх C0 (`c5ff58f`).

## Реализованная граница

`LocalizationProjectConfig` — определения проекта: языки, Main и дополнительные
каналы, наборы, записи, стартовые наборы, адреса источников и оформления.
В нём нет выбранного игроком языка, загруженных таблиц, шрифтов или runtime-задач.
`Create(new[] { "en", "ru" })` создаёт Main/Common в памяти. Сохранение asset
делает Editor API; настройка в основном окне подключается в C5.

`LocalizationLanguageDefinition` содержит код/название/системный язык и
необязательный адрес оформления. `LocalizationAppearance` — отдельный загружаемый
asset со шрифтами, типографикой и layout. Корневой конфиг хранит строковый адрес,
а не Unity-ссылку на этот asset. Отсутствие оформления сохраняется как null через
SerializeReference; inline-сериализация обычного класса Unity заменяла null
пустым объектом, что выявил round-trip тест.

На этом шаге старая модель остаётся подключённой к старому runtime/окну/демо.
Новый runtime подключается в C2–C4, окно — C5, данные — C6. Это промежуточное
состояние перехода, не второй движок и не окончательное предложение нескольких
проектных конфигов пользователю. Старые типы/меню удаляются при переключении
соответствующих потребителей; автоматического мигратора не будет.

## Идентификаторы и ссылки

- Канал/набор/запись: непустой GUID в 32-символьном нижнем регистре, без дефисов.
  ID генерируется при создании, не вычисляется из имени и не равен Unity GUID.
- ID виден в Inspector read-only. Списки API read-only, изменение определений
  выполняется методами/свойствами авторинга. Unity-данные всё равно валидируются
  перед построением индекса: Inspector/внешняя правка могут обойти API.
- Main и набор по умолчанию каждого канала задаются по ID. Переименование Common
  не меняет назначение короткого чтения. Удаление default-набора не выбирает
  другой автоматически: нужно явно указать замену из оставшихся привязок.
- `LocalizationEntryReference` содержит channelId и entryId. Переименование и
  перенос сохраняют entryId. Перенос в недоступный каналу набор возвращает
  SetNotAvailable, не подменяет канал. Удаление и повторное создание того же
  ключа не перенаправляют старую ссылку на новую запись.
- `LocalizationEntryIndex` копирует только маршрутизацию. Изменение исходного
  конфига не меняет уже построенный индекс. Строковый ключ остаётся удобным
  адресом внутри набора, его произвольное переименование не обещает исправить
  строковые литералы в пользовательском коде.
- Дубли ID во всём проекте и ключей внутри набора — ошибки. Конфликт переноса
  проверяется до удаления исходной записи. Импорт может передать существующий ID;
  конфликты между наборами выявляются общей валидацией.

## Языки, fallback и источники

Канонизация языковых кодов и реестр IANA перенесены из Editor в runtime. Окно
использует тот же код. Поддерживается прежнее подмножество BCP-47 с script/region/
variants и x-...; это не новый полноценный парсер всех расширений BCP-47.
ISO3-алиасы используют доступные .NET cultures, как прежний каталог редактора.

Independent/FollowMain — единственные режимы. Main не может следовать себе.
Канал выбирает языки из проектного каталога; default и необязательный fallback
из своего списка. Явные fallback-рёбра переопределяют общее правило. При отсутствии
ребра используется fallback канала; сам язык fallback завершает цепочку. Циклы
проверяются с учётом этих неявных переходов.

FollowMain может иметь меньше доступных языков, чем Main. В C3 при отсутствии
запрошенного Main-языка стартом разрешения будет default следующего канала, затем
его fallback-цепочка. Запрошенный язык и язык результата остаются различимыми.
Это не смена языка независимых каналов и не требование переводить голос на все
языки интерфейса.

`LocalizationSourceReference` содержит providerId/address/kind. Resources требует
точного безопасного относительного адреса. Другие провайдеры могут использовать
свои URI/идентификаторы; валидация C1 не обращается к сети/диску и не доказывает,
что источник существует. Проверка регистрации/возможностей провайдера — C2.

`PluralRuleProvider.GetRuleInfo` сообщает BuiltIn/Custom/Default вместе с реально
используемым правилом. Для общего английскоподобного правила конфиг возвращает
warning `default-plural-rule`, не запрещая выбранный язык. Региональный override
и родительский custom имеют тот же приоритет, что при реальном форматировании.
Этот статус не подтверждает полное CLDR, shaping или наличие символов в шрифте.

модели/валидации/сериализации, старые проверки окна и форматирования также прошли.
Локальные полные результаты: `TestResults/Channels-C1/editmode.json`,

Проверка Player, платформ и фактического переключения новых каналов относится
к следующим этапам, этим прогоном не подтверждается.

В C2 необходимо
сохранить объявленную гранулярность загрузки, а в C3 — построить неизменяемое
состояние экземпляра из этих определений. Новые каналы пока не переключают сцену.
Оставшийся глобальный plural-override API относится к старому пути; изолированный
runtime не должен зависеть от изменяемых глобальных overrides (C3/C4).
