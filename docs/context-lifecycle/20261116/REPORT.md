# Этап 9: готовность и жизненный цикл — итоговая проверка

Дата: 2026-11-16. Unity 6000.0.62f1, Windows. Ветка dev/localization-stability, база c939b18 с рабочими изменениями завершения этапа 9. Это проверка рабочей версии после package.json 2.0.2, не опубликованного тега.

## Что изменилось

LocalizationContext объединяет точную загрузку Resources, ожидание аудиоданных, проверку лимитов и атомарную смену языка. Ошибка или отмена не заменяет активный набор. Чтение готовых данных не вызывает провайдер. Новый запрос отменяет старого кандидата и ждёт его очистки, поэтому кандидаты не накапливаются.

Owned — явный договор владения. Плагин учитывает общие ресурсы и ожидающие загрузки, освобождает их после последнего контекста. Borrowed сохраняет ресурсы; смешанное использование удерживает общий объект до последнего пользователя. Отмена не прерывает Unity ResourceRequest: ReleaseAsync дожидается поздних результатов и освобождает учтённые ресурсы. Пользовательский ScriptableObject может объявить зависимости через ILocalizationAssetDependencies; пример — HorrorVisualVariant со своей текстурой.

Лимиты ограничивают исходный JSON до разбора, текстовые записи/символы, ассетные записи и шаблоны. При переходе одновременно существуют прежний активный набор и один кандидат. Реестр получает новую сессию при SubsystemRegistration; старые контексты не могут выгрузить ресурсы нового Play Mode.

Сигнатуры существующих API, сериализованные данные и сторонние провайдеры сохранены. Старый LocalizationManager не начинает автоматически выгружать ресурсы. В пакете добавлены только runtime-контракты; регрессии/пробники находятся в полигоне. Сценарий основной настройки через окно Simply Localize не менялся.

Полные JSON EditMode/PlayMode убраны из текущего дерева 2026-11-17; сводные числа выше сохранены. [Хранение и восстановление](../../ARTIFACT_POLICY.md). Последний EditMode выполнен до дополнительной проверки поколения после ожидания аудио; итоговый PlayMode и все три Player используют окончательный runtime, включая эту защиту. Этот guard не меняет редакторские ветви без проигрывания.

Добавлено 9 EditMode и 8 PlayMode случаев. EditMode проверяет готовые чтения, ограничение шаблонов, fallback, лимиты/копирование настроек, malformed JSON, сохранение активного состояния, отмену/последний запрос, закрытие незавершённой операции, исключение подписчика после применения, повторные переключения и отсутствие скрытой загрузки после изменения конфига. Слишком большой JSON отклоняется до парсинга.

PlayMode проверяет Loaded, двух владельцев, смешанное Borrowed/Owned, отсутствие выгрузки только заимствованных ресурсов, позднюю отмену, очистку не прошедшего лимит кандидата, закрытие владельца при ожидающем втором запросе, конкурентный старт и переход между поколениями реестра. Последний случай вызывает reset через reflection; ручной запуск нескольких Play Mode с отключённым Domain Reload этим не подменяется.

В ходе подготовки тестов четыре первоначальные проверки освобождения оказались неверными: сравнение persistent AudioClip/Texture с null в Editor не всегда доказывает отсутствие native-объекта. Итоговые тесты проверяют отсутствие сохранённого Instance ID в Resources.FindObjectsOfTypeAll; свежий Player дополнительно проверяет null. Это исправление критерия теста, не обход в runtime. Обоснование: редакторская семантика восстановления persistent-объектов в [Unity 6000.0 Object bindings](https://raw.githubusercontent.com/Unity-Technologies/UnityCsReference/6000.0/Runtime/Export/Scripting/UnityEngineObject.bindings.cs).

## Границы результата

Owned требует отсоединить AudioSource/материалы и другие игровые потребители до ReleaseAsync. Ссылки обычного Resources.Load, старого менеджера или сцены вне учёта контекста не защищены. Prefab/GameObject, Component и AssetBundle требуют Borrowed. Автоматический граф всех зависимостей материалов/шрифтов не заявляется; расширяемые зависимости объявляются явно.

Loaded не равен нулевой физической задержке звука или полной распаковке streaming-файла. При выключенном Load In Background вызов LoadAudioData может блокировать главный поток. Аудиотайм-аут не обещает прервать внутреннюю native-загрузку; закрытие ждёт её окончания. Зависшие Unity-запросы и остановленные кадры могут не дать очистке завершиться.

Лимиты логические, не жёсткий бюджет RAM; Unity загружает прямые зависимости таблиц до проверки записей. JSON пока разбирается на главном потоке. Не проверены 1k/10k/100k таблицы, полные CJK/RTL-наборы, бюджеты шрифтов, WebGL/IL2CPP и другие версии Unity. Это этапы 10/11. Глобальный UnloadUnusedAssets и принудительный GC не используются.

Этап 9 завершён в указанном контракте. Следующее действие — [ручная приёмка](../MANUAL_TESTS.md), затем согласованный переход к этапу 10.
