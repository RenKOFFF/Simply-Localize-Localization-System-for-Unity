# Контекст локализации: готовность, владение и лимиты — завершение этапа 9

LocalizationContext объединяет загрузку выбранных источников, подготовку аудио, проверку лимитов и применение языка. Игра получает уже готовое состояние; при ошибке продолжает работать прежнее. Для обычных небольших проектов старые Localization/LocalizationManager/ResourcesDataProvider остаются без изменений.

## Использование

```csharp
var context = new LocalizationContext(config, new[]
{
    new ResourcesLanguageSources("en", assetTables: new[] { "Localization/en/Radio" }),
    new ResourcesLanguageSources("ru", assetTables: new[] { "Localization/ru/Radio" })
}, new LocalizationContextOptions
{
    Ownership = LocalizationResourceOwnership.Owned,
    PrepareAudio = true,
    MaxAssetEntries = 100
});

await context.ChangeLanguageAsync("ru", cancellation);
var voice = context.ResolveAsset<AudioClip>("Radio/01");
if (voice.Status == LocalizationResolveStatus.Found)
{
    audioSource.clip = voice.Value;
    audioSource.Play();
}

// Сначала отсоединить игровые потребители, затем закрыть контекст.
audioSource.Stop();
audioSource.clip = null;
await context.ReleaseAsync();
```

Для чисто голосового/визуального конфига укажите loadTextData=false. Если нужен текст, перечислите textFiles у ResourcesLanguageSources. context.Get(key, args) форматирует перевод, ResolveText возвращает исходное значение и фактический язык источника, ResolveAsset<T> возвращает ресурс и язык fallback. Эти операции не загружают данные. ResourceRequestCount показывает запросы самого контекста.

ChangeLanguageAsync можно вызвать и для текущего языка: это свежая подготовка. Последний запрос отменяет предыдущий; новый кандидат начинает загрузку после завершения очистки отменённого. Активный набор остаётся доступным до успешного применения. Событие OnLanguageChanged вызывается после публикации; исключение подписчика не откатывает уже применённое состояние. Dispose запускает закрытие; ReleaseAsync позволяет дождаться всех запросов и освобождения. Повторное закрытие возвращает ту же задачу.

## Владение

По умолчанию Ownership=Borrowed. Контекст освобождает свои ссылки и не инициирует выгрузку native-ресурсов.

Owned включается явно. Это договор: ресурсы набора используются только через живые контексты; сырые ссылки нельзя использовать после закрытия их владельцев. Перед закрытием нужно остановить AudioSource, убрать текстуры из материалов/MaterialPropertyBlock и отсоединить прочих потребителей. Не включайте Owned, если те же объекты используются обычным Resources.Load, старым менеджером или сериализованными ссылками сцены без учёта их времени жизни.

Объекты учитываются по Unity Instance ID. Два контекста с общим ресурсом сохраняют его до закрытия последнего. Ожидающие запросы тоже удерживают ресурс: первый завершившийся контекст не может выгрузить данные из-под ещё загружающегося. Borrowed-контекст также удерживает общий объект, если другой контекст объявил его Owned; после закрытия последнего из них объект будет выгружен. Одни только Borrowed-контексты native-выгрузку не запускают.

При отмене контекст ждёт уже начатые ResourceRequest, учитывает поздние объекты и освобождает их. Это может занять время: Unity-запрос не прерывается посередине. При закрытии во время LoadAudioData освобождение ждёт завершения этой операции. Если Unity перестала обновлять кадры или native-запрос завис, ожидание тоже не сможет закончиться. Глобальные UnloadUnusedAssets и принудительный GC не используются. При новом запуске Play Mode реестр получает новую сессию: старые контексты становятся недействительными и не могут выгрузить ресурсы новой сессии. Это защита при отключённом Domain Reload, а не обещание завершить асинхронную очистку после остановки Unity; закрывайте контексты до выхода из Play Mode.

Owned работает в PlayMode/Player, не при редакторском редактировании. Поддерживаются дисковые Unity-ассеты, допускающие Resources.UnloadAsset. Prefab/GameObject, Component и AssetBundle для этого режима не поддерживаются: используйте Borrowed. Для материалов, шрифтов и произвольных SO не обещается автоматическое перечисление всех скрытых зависимостей. [Ограничения Unity UnloadAsset](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Resources.UnloadAsset.html).

## Собственные типы ресурсов

Записи LocalizationAssetTable и текстуры Sprite учитываются автоматически. Собственный ScriptableObject может реализовать ILocalizationAssetDependencies:

```csharp
public IEnumerable<UnityEngine.Object> GetLocalizationDependencies()
{
    yield return texture;
}
```

Возвращайте только дополнительные runtime-ресурсы, жизнью которых должен управлять этот контекст. Не включайте общие профили, конфиги и чужие объекты. Повторы и циклы обрабатываются. В Night Shift HorrorVisualVariant объявляет свою текстуру, а LanguageProfile остаётся во владении общей конфигурации. Расширение пишется в проекте игры, без форка пакета. Старые сторонние ILocalizationDataProvider/IAsyncLocalizationDataProvider продолжают работать с LocalizationManager; новый контекст предназначен именно для перечисленных Resources-источников.

## Готовность аудио

При PrepareAudio=true контекст вызывает LoadAudioData для Unloaded-клипов и ждёт состояния Loaded у всех выбранных клипов, включая fallback и объявленные зависимости. Failed, отказ LoadAudioData или тайм-аут приводят к ошибке подготовки и сохранению прежнего языка. Отмена тоже не публикует частичное состояние.

Loaded — состояние Unity AudioClip. Для streaming-аудио оно не означает, что весь файл декодирован в RAM; также это не гарантия нулевой задержки звукового устройства. LoadAudioData при выключенном Load In Background может выполнять работу синхронно. Для фоновой подготовки настройте импорт соответствующим образом. [Unity LoadAudioData](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AudioClip.LoadAudioData.html).

## Лимиты

| Настройка | По умолчанию | Что ограничивает |
|---|---:|---|
| MaxSourceCharacters | 4 000 000 | Размер одного JSON до разбора |
| MaxTextEntries | 100 000 | Сумма текстовых записей активного языка и fallback |
| MaxTextCharacters | 16 000 000 | Сумма UTF-16 символов ключей и значений |
| MaxAssetEntries | 4 096 | Записи выбранных таблиц, включая fallback |
| MaxTemplates | 1 024 | Количество разобранных шаблонов; при заполнении кэш сбрасывается |
| AudioTimeoutSeconds | 30 | Ожидание готовности аудиоданных |

Лимиты положительные и копируются при создании контекста. Превышение не заменяет активное состояние. Старые языки и шаблоны не накапливаются: после переключения прежний набор освобождается. Пока готовится новый язык, одновременно существуют активный набор и один кандидат. Это логические лимиты, не жёсткий бюджет байтов RAM: загрузка TextAsset/таблицы и её прямых зависимостей происходит до проверки содержимого, а Unity и ОС имеют свои кэши. Разбор JSON пока выполняется на главном потоке. Большие таблицы и замеры 1k/10k/100k относятся к этапу 10.
