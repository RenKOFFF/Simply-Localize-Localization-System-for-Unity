Редакция 1.1 (только хранение артефактов; измерения редакции 1.0 не изменены). Дата пользователя: 2026-11-17 (Asia/Yekaterinburg), записи UTC — 2026-11-16, поэтому каталог имеет суффикс 20261116. Проверенная ревизия acb8433, ветка dev/localization-stability, Night Shift 1.4.0, Unity 6000.0.62f1, Windows/D3D11. Пользователь также сообщил об успешном самостоятельном ручном проходе.

## Методика

Сценарии из MANUAL_TESTS выполнены в открытом Editor через Unity CLI, с осмотром реальных кадров Game view. Это управляемая проверка живого интерфейса, не заявление о физическом ручном вводе человека или прослушивании. Открывались реальные TMP dropdown, выбирались Toggle и нажимались Button через EventSystem; первый выбор русского голоса дополнительно выполнен simulate_pointer down/up. Начальный ввод в нефокусированное окно не обработался; после фокуса Game view выбор сработал. Продвижение Time.frameCount проверено job wait, окна/сцены не подменялись макетами.

При запуске использовались одноразовые Stage9Acceptance.cs и VisualAcceptance.cs, компилируемые через script run в память. Второй ставил игрока перед табличкой, затем использовал обычный поиск знака и HUD; это не проверка прохождения пути WASD. Скрипты и дубли кадров удалены 2026-11-17 по [правилам хранения](../../ARTIFACT_POLICY.md); при необходимости доступны из ревизии 3ff7139. Результаты и уникальные свидетельства сохранены.

Реестр владения читается reflection только в диагностическом скрипте. Эти снимки создают временные списки и не подходят для измерения CPU/GC. Глобальная выгрузка/принудительный GC не использовались. Новый Player не собирался: результаты этого прохода относятся к Editor; предыдущие Player-доказательства сохраняются отдельно.

При тесте Borrowed после проверки внешняя ссылка отброшена, затем отдельный явно Owned-контекст загрузил и штатно освободил свой набор. Это уборка изолированного тестового содержимого после фиксации результата Borrowed, не доказательство того, что Borrowed умеет выгружать ресурсы.

В исходном служебном console-delta.json (удалён при очистке) не было новых сообщений после исходного cursor=226. Счётчики counts — накопленная история предыдущих тестов редактора, не ошибки текущего запуска; groundTruth также показывает 0 ошибок/предупреждений. Подписка на логи внутри каждого сценария не обнаружила новых warnings/errors. Диагностический запрос материала сначала упал внутри script eval из-за проверки Contains у null-текста; повтор с проверкой null выполнен. Это ошибка диагностического запроса, не исключение игры.

Настройки Enter Play Mode возвращены в исходные enabled=false/options=None; оба файла ProjectSettings/EditorSettings побайтово совпадают с исходными копиями. Пять PlayerPrefs стенда восстановлены, Play остановлен, сцена NightShiftMenu без несохранённых изменений. Исходное пользовательское состояние ProjectSettings.asset не включается в коммит.

## Обнаружено и записано в реестр

- **NS-UI-001, P3, стенд:** стрелки dropdown отображаются белыми квадратами, на белом фоне пропадают. Видно в 03-world-dialogue.png и 09-polish-render-recheck.png. HorrorHud создаёт TMP_DefaultControls.Resources без графики arrow/checkmark. Выбор языка работает, но визуальная подсказка нечитабельна.
- **NS-UI-002, P3, стенд:** при Test radio с открытым меню панель субтитров перекрывает нижнюю подпись меню. 03-world-dialogue.png. Перевод корректен; требуется развести размещение меню/субтитров.
- **SL-013, P2, риск по коду:** ReleaseAsync перебирает Addresses для каждого освобождаемого объекта. Верхняя оценка работы очистки адресов O(R×A), временные LINQ/ToArray, плюс отдельные native unload. Большие наборы не измерялись: это не доказанный скачок кадра. Исправление/бенчмарк не выполнялись.
- **SL-014, запрос диагностики:** нет штатного объяснения, какой контекст удерживает ресурс и почему он не освобождён. В текущей проверке потребовалось читать private-реестр. [Предложение панели](../OWNERSHIP_AND_DIAGNOSTICS.md).
- **SL-004, подтверждение прежнего ограничения:** два контекста запросили Radio/01, но выбранная таблица удерживает все три клипа Radio. Это ожидаемая гранулярность таблицы, не AssetBundle и не новая утечка.

**Неподтверждённое наблюдение QA-CAPTURE-001:** в быстро сделанных ScreenCapture.CaptureScreenshot кадрах warning-Off/Always есть неполные буквы HUD. warning-Auto и повторный стабильный захват через CLI 08/09 показывают полный текст, в том числе тот же польский заголовок. Пока нельзя отделить временный рендер от механизма захвата; к дефектам локализации это не отнесено. Кадры сохранены, вопрос не скрыт. Для подтверждения нужен независимый захват экрана/видео или воспроизведение пользователем; корректный повтор сам по себе не доказывает, что исходный симптом невозможен.

Новых функциональных отказов локализатора в проверенных сценариях нет. Физическая задержка звука, большой масштаб, полная матрица платформ и RAM-профиль не проверены. Этап 10 не начат; исходники runtime и стенда не исправлялись.

## Воспроизведение

Открыть NightShiftMenu на проверенной ревизии, сохранить свои предпочтения/настройки, войти в Play и подтвердить движение кадров. Для точного повторения восстановить одноразовые скрипты из 3ff7139; через Unity CLI выполнить script run с абсолютным file=Stage9Acceptance.cs, entry=Stage9Acceptance.Main, args=["first"], затем fallback, cycles, cancel, owners. Скрипты пишут по указанному в них пути: для нового запуска заменить Root/пути отчёта, чтобы не перезаписать эту запись. Для session1/session3 включать DisableDomainReload между остановленными Play; второй раз остановить Play из готового мира. После закончить Play и восстановить настройки/предпочтения.
