# Подготовка локализации — этап 9.1

Дополнение этапа 9.2: [ScopedResourcesDataProvider](../scoped-resources/README.md) уже поддерживает реальные асинхронные запросы по явно выбранным адресам. Обычный ResourcesDataProvider, описанный ниже, остаётся синхронным.

Теперь можно явно разделить две операции: подготовить данные перед входом в сцену и затем получать уже подготовленные значения. Это дополнительный путь: старые SetLanguage, Get, GetAsset, Reload и пользовательские провайдеры продолжают работать. Формат JSON, конфигов и таблиц не меняется.

## Пример для Resources

```csharp
var manager = new LocalizationManager(config);
using (var prepared = manager.PrepareLanguage("ru", includeAssets: true,
    cancellationToken: cancellation))
{
    // Пока подготовка не применена, активный язык и события не меняются.
    manager.ApplyPreparedLanguage(prepared, cancellation);
}

var voice = manager.ResolvePreparedAsset<AudioClip>("Radio/01");
if (voice.Status == LocalizationResolveStatus.Found)
{
    audioSource.clip = voice.Value;
    // voice.RequestedLanguage — выбранный язык.
    // voice.ResolvedLanguage — язык таблицы, реально давшей значение.
    // Наличие AudioClip ещё не означает готовность декодированного звука.
}
```

PrepareLanguage читает свежие данные выбранного языка и всей его fallback-цепочки в пределах текущего провайдера. При includeAssets=false таблицы не читаются; при config.loadTextData=false не читается текст. Resources выполняет эту работу синхронно на Unity-потоке. Метод не обещает отсутствие зависания при большом наборе.

ApplyPreparedLanguage заменяет активные кэши подготовленным набором, очищает старые разобранные шаблоны и после этого вызывает обычные события смены языка/профиля. Сам метод не читает провайдер; сторонние обработчики событий могут выполнять свою работу. Исключение обработчика возникает уже после применения состояния и не откатывает его.

Dispose снимка убирает только его управляемые ссылки. Применённый менеджер сохраняет свои копии коллекций. Таблицы и Unity-объекты не копируются и остаются во владении провайдера/его владельца. Пока они используются, владелец не должен менять или выгружать их. Два менеджера могут использовать один провайдер; освобождение снимка одного не уничтожает данные другого.

## Получение без загрузки

ResolvePreparedText и ResolvePreparedAsset не обращаются к провайдеру — в том числе при отсутствии ключа. Они различают:

- Found — непустой перевод или ресурс найден; указан фактический язык источника.
- Missing — проверенные подготовленные данные не содержат подходящего значения.
- NotPrepared — для ответа не хватает загруженной части цепочки либо канал не включён/язык ещё не выбран.

Доступ работает и с кэшами, заполненными старым API. Проверка останавливается на первом подходящем значении, поэтому не требует последующих fallback-таблиц, если текущий язык уже дал ответ. ResolvePreparedText возвращает исходный текст, без подстановки параметров; обычный Get сохраняет форматирование. ResolvedLanguage обозначает язык источника, а не автоматически распознанный язык надписи внутри картинки.

## Отмена, ошибки и устаревшие результаты

Ошибка провайдера или отмена подготовки не изменяет активный язык, кэши и события. Синхронный вызов провайдера прервать посередине нельзя: токен проверяется между вызовами и перед применением.

Снимок применяется только к создавшему его менеджеру. Он становится устаревшим после успешной смены языка/провайдера, Reload, ClearCaches или другого применения; проверяются также настройки загрузки, выбранный профиль и fallback-цепочка. Изменения самих внешних данных без уведомления менеджера не обнаруживаются: вызовите Reload или подготовьте новый снимок. Освобождённый или чужой снимок отклоняется.

## Асинхронный пользовательский провайдер

```csharp
manager.SetDataProvider(myAsyncProvider); // IAsyncLocalizationDataProvider
using (var prepared = await manager.PrepareLanguageAsync("ru",
    cancellationToken: cancellation))
{
    manager.ApplyPreparedLanguage(prepared, cancellation);
}
```

Необязательный IAsyncLocalizationDataProvider дополняет прежний ILocalizationDataProvider двумя методами Task для текста и таблиц. Вызов и продолжение должны выполняться на Unity-потоке менеджера; перенос Unity API в Task.Run не используется. Асинхронный провайдер отвечает за своё логирование и очистку частично выполненной работы. Отмена прекращает ожидание даже провайдера, который игнорирует токен; она не останавливает его внутреннюю операцию и не выгружает её ресурсы. Поздний результат не применяется, поздняя ошибка наблюдается.

Стандартный ResourcesDataProvider пока не реализует этот интерфейс. PrepareLanguageAsync с ним явно возвращает NotSupportedException; используйте синхронный PrepareLanguage. Настоящая ограниченная асинхронная загрузка — отдельный следующий шаг.

## Что пока остаётся

Границы загрузки по отдельным таблицам/ключам, большой соседний ассет, native release с несколькими владельцами, ожидание аудиоданных, бюджеты памяти и асинхронный Resources ещё не реализованы. Прямые ссылки таблицы по-прежнему вовлекают её зависимости. Новый apply сохраняет только подготовленную цепочку, но не вводит общий бюджет и не меняет прежнюю политику кэша SetLanguage/GetAsset.

Результаты и ограничения проверки: [отчёт](20261116/REPORT.md).
