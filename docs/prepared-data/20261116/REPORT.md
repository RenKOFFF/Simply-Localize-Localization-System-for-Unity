# Этап 9.1 — подготовка данных и чтение без провайдера

2026-11-16. Unity 6000.0.62f1, ветка dev/localization-stability. База c2ebb60a9338ae40c4f4d4ab2566e74574768082 плюс изменения этого этапа. Это первый завершённый шаг этапа 9, а не завершение всей ресурсной архитектуры.

## Результат

Добавлены PrepareLanguage, PrepareLanguageAsync, ApplyPreparedLanguage и ResolvePreparedText/Asset. Подготовка создаёт отдельный снимок; ошибки и отмена оставляют активное состояние прежним. Применение заменяет кэши без чтения провайдера. Доступ к готовым данным различает NotPrepared/Missing/Found и сообщает фактический язык fallback. Старые API, сторонние синхронные провайдеры и сериализованные данные сохранены.

Async-путь доступен сторонним реализациям нового необязательного IAsyncLocalizationDataProvider. Resources остаётся синхронным: никакого переноса Unity API в Task.Run. Dispose снимка освобождает его ссылки, но не уничтожает провайдер или Unity-объекты. Подробные контракты и примеры — в [руководстве](../README.md).

## Проверки

- [EditMode](editmode.json): 411/411, без пропусков; 28 новых случаев. Ошибки/пустой ответ провайдера, отмена до/во время подготовки и перед apply, отмена ожидания некооперативного async-провайдера, поздний результат, конкурирующие подготовки, чужой/освобождённый/устаревший снимок, события после commit, два менеджера с общими ресурсами, копирование коллекций, отключённые каналы, повторные переключения и границы кэша.
- [PlayMode](playmode.json): 27/27, без пропусков; один новый тест реального Resources. Внутри 1 000 повторений проверяются существующий клип и отсутствующий ключ; обращений к провайдеру после применения — 0. Прежний первый GetAsset даёт 1 обращение. Подготовка ru/en даёт 2 чтения таблиц, 6 записей. [Сырые измерения](playmode-probe.json).
- [Windows Release Player](../../playground-journal/night-shift/runs/20261116T170733Z_nightshift-1.2.0_c2ebb60/REPORT.md): сборка без ошибок/предупреждений, exit 0, 197 утверждений пройдены. Три входа в мир: первые диалоги дают 0/0/0 чтений провайдера. Direct3D11, реальное продвижение кадров — по 120 кадров на мир.

PlayMode-проба заранее получает таблицы для выбора ключа и не является холодным дисковым замером. Её таймеры включают проверки. Player использует маленькую фикстуру и лимит 60 FPS. Сравнение подтверждает перенос вызовов провайдера из первого диалога в подготовку; оно не доказывает ускорение всей загрузки или поддержку больших объёмов. Общее время с прежними протоколами напрямую не сравнивается.

## Что осталось

SL-003 устранён для нового opt-in пути; legacy GetAsset по-прежнему может загружать. SL-007 доступен через новый результат разрешения; язык источника не подменяет авторские метаданные картинки. SL-012 ограничен текущей цепочкой только при ApplyPreparedLanguage, без общего бюджета памяти.

SL-002 (настоящий async Resources), SL-004 (зависимости больших таблиц), SL-005 (native release и несколько владельцев), SL-006 (готовность аудиоданных) остаются открыты. В Player первые два языка дали Unloaded перед Play; после выходов осталось 3/6/6 AudioClip. Это наблюдение, не доказательство утечки. Большой соседний ассет и масштабы тысяч/сотен тысяч записей здесь не проверялись.

Следующий шаг 9.2: согласованный контракт владения и ограниченных наборов ресурсов, затем реальная async-загрузка Resources и отдельная готовность аудиоданных. Addressables и файловые пользовательские переводы в этот шаг не входят.
