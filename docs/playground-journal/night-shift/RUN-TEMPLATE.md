## Что изменилось с предыдущего запуска

Ссылка на предыдущий run. Изменения плагина отдельно от изменений стенда/данных. Можно ли сравнивать метрики напрямую?

## Результат

Функциональные проверки: passed/failed и причина. Находки по каждому ID: воспроизведено / не воспроизведено / не проверялось. Не подменять общий статус отсутствием исключений.

## Метрики и границы

Первый доступ и повторный доступ отдельно; операции настройки контекста не называть подготовкой контента. Указать, что именно замерено: вызов Play или готовность данных/физический звук. RAM/native/audio/GPU не смешивать. Зафиксировать кап FPS, состояние сцены, прогрев, точки измерений и влияние самого теста.

## Что исправлено / что осталось

ID → commit исправления → новый регрессионный тест → доказательство. Исчезновение симптома после очистки в стенде не закрывает ошибку плагина.

## Артефакты

В новую runs/<runId>/ скопировать player.json, player.log, build-identity.json, editor-checks.txt, build.txt, package.json и зависимости. Сохранить код проверки/хеши; не коммитить Player/Library/кэши. При повторном использовании runId остановиться и выбрать новый, не перезаписывать прошлый запуск.

Сначала проверить совпадение buildIdentity в player.json и build-identity.json. Если Git отсутствует в PATH Unity, перед сборкой указать NIGHTSHIFT_GIT. unavailable нельзя молча заменить догадкой о commit.

Текущий отпечаток стенда включает .meta файлов Content. Сохраняйте их отдельно вместе с исходниками, как в существующих запусках, и проверяйте восстановление хеша из архивов. Не сравнивайте отпечаток без этих файлов с playgroundSourceSha256 собранного Player.
