## Правила для следующих запусков и исправлений

1. Записывать новый runId; старые отчёты и исходные результаты не перезаписывать.
2. Разделять изменения плагина, изменения стенда, изменения данных и окружения.
3. Перед публикацией записи проверять совпадение buildIdentity из Player и сборки, а также соответствие исходников их хешу.
4. functionalChecksPassed относится только к перечисленным функциональным утверждениям. Он не закрывает findings, не доказывает отсутствие утечек и не подтверждает масштабирование.
5. Закрывать проблему по её критерию из ISSUES.md: commit исправления, регрессионная проверка, новый результат. Обход в стенде не является исправлением плагина.
6. При изменении методики менять measurementProtocol и описывать допустимость сравнения метрик. Версию стенда менять независимо от версии локализатора.
7. Указывать dirty/unavailable состояния явно. Не выдавать результат другой ревизии за проверку опубликованного тега.
8. Сохранять подробные отчёты, исходные результаты и инструкции воспроизведения. Краткие пользовательские объяснения остаются в переписке.
