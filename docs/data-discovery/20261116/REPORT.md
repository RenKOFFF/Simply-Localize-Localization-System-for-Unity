# Этап 8: обнаружение данных и Coverage

Unity 6000.0.62f1, ветка dev/localization-stability, база ee9ce04.

## Исправления

Редактор собирает список JSON из всех настроенных языков. Если extra.json есть только в русском, его ключи теперь видны в Translations и сохраняются в исходный файл. Пустые слоты профилей и отсутствие папки основного языка не мешают загрузить другие языки.

Вложенные источники различаются по относительному пути: chapter1/main и chapter2/main. Сохранение, клонирование данных, CSV и переименование ключей сохраняют эти пути. Уже существующие вложенные источники разрешены в CSV; ограничение безопасного одиночного имени для создания нового источника через CSV осталось прежним. Дополнительные поля JSON сохраняются. Регистр существующего расширения файла также сохраняется.

Проверка JSON и владельцев ключей выполняется до публикации набора данных. Повреждённый документ, повторяющиеся JSON-поля, конфликт регистра имён и один ключ в разных исходных файлах дают LoadError. Сохранение блокируется до исправления и Reload; частичные данные не становятся основой перезаписи. Основное окно показывает причину и кнопку Reload data. Settings, Profiles, Languages и Coverage остаются доступны для диагностики и настройки.

Выбор конфига общий для окна и инспекторов: явный выбор пользователя → фиксированный стартовый конфиг → единственный найденный конфиг. При нескольких кандидатах без явного выбора редактор предлагает выбрать Config в верхней части окна. Выбор редактора не меняет runtime-конфигурацию или autoInitialize. Есть EditorDataCache.SelectConfig для внешних Editor-скриптов. В поиске отбрасываются чужие типы с таким же коротким именем класса.

## Несколько Resources: явная граница

Разные Resources-папки с разными адресами данных поддерживаются. Если один resourcesBasePath существует в нескольких физических папках, редактор сообщает все найденные расположения и блокирует запись. Проверка повторяется перед сохранением, если новая конфликтующая папка появилась после загрузки.

Это **не реализация объединённого редактирования распределённого набора**. Для записи из окна нужен один однозначный каталог данных. Автоматического переноса/слияния файлов нет. Runtime по-прежнему может читать данные из нескольких Resources через существующий провайдер; его правила не менялись. Такое ограничение защищает от прежнего молчаливого выбора первой папки и потери данных при сохранении.

Папки Editor исключаются из выбора игровых Resources. Данные локального UPM-пакета распознаются по реальному пути PackageInfo, но не редактируются через этот редактор: он сообщает, что данные находятся в пакете. Внутренние тестовые данные после проверок удаляются.

## Coverage и SL-008

В каждой строке доступны три разных показателя:

- Entries: число существующих записей.
- Direct: число непустых значений самого языка.
- With fallback: число значений, доступных с учётом fallback.

EmptyKeys, WhitespaceKeys и UnavailableKeys дополнительно доступны через Editor API и подсказку строки. Пустая запись отличается в предупреждениях от отсутствующей. Пробельная строка получает отдельное предупреждение; она остаётся значением для runtime и не запускает fallback.

При построении снимка Coverage больше не создаёт синтетические пустые записи в соседних языках. Актуальный полный снимок данных редактора учитывает удаления, ещё не отражённые в импортированных TextAsset. Частичные программно созданные снимки по-прежнему накладываются поверх данных провайдера. Данные другого Resources-пути не накладываются на выбранный конфиг. Ошибка обнаружения отмечает проверку как неполную.

Поведение HasKey, возврат ключа при отсутствии перевода, форматирование, fallback и загрузчики **не менялись**. Strict-режим не добавлялся. IsComplete по-прежнему означает отсутствие ошибок самой проверки, а не 100% переведённых строк. Отчёт не гарантирует, что переданы все ключи, используемые строковыми литералами в игровом коде.
